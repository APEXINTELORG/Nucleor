## Bug shape (the gap this closes)

Per RFC-0062 §3.3 G-11: "TYP-008 already rejects `let mut x: i64;` even
when every branch assigns. Strict but loud." Phase 1 lock-in fixtures
(`tests/err/err_g11_uninit_simple.nr`, `tests/err/err_g11_uninit_branch.nr`)
explicitly noted: "Phase 2 may relax this if/when the definite-assignment
pass lands; until then this fixture locks the v0.x behavior."

Phase 2b spec: "Track per-binding 'assigned-on-every-incoming-path' bit
at every read. Relax TYP-008 when satisfied." Phase 4 promotes the new
diagnostic to a hard error.

## Patch shape

Five additive edits to `compiler/nucleor_s1_compiler.nr`:

1. **Diagnostic registration** (line ~11157). Add
   `INIT-G11-READ-BEFORE-INIT` to `is_error_code`. Phase 4 promotion
   via `own_diag` (always emits at error severity).

2. **TYP-008 narrowing in `type_check_stmt` kind 20** (line ~23647).
   Pre-Phase-2b TYP-008 fired on every no-init `let`. Now gates on
   `is_mut_g11 == 0` — only IMMUTABLE no-init still rejects (`let x: T;`
   is structurally unreachable: never settable). Mutable no-init
   (`let mut x: T;`) is permitted; the new INIT-G11-READ-BEFORE-INIT
   takes the runtime-soundness role.

3. **Init-state tracking in `check_stmt` kind 20** (line ~19954-19957).
   On let-decl: if init >= 0, set `__init_<vname> = 1` (definitely
   assigned at decl). Else, set `__init_<vname> = 0`. Both paths set
   `__init_seen_<vname> = 1` (sentinel — distinguishes DA-tracked
   bindings from params / loop vars / etc. that don't go through this
   path).

4. **Init-state set on assignment in `check_stmt` kind 21** (line ~19982).
   For kind-3 var-ref LHS: `own_set_i_raw(own, "__init_<lname>", 1)`.
   Definitely assigned at this program point.

5. **Read-before-init check in `check_expr` kind 3** (line ~19461,
   *before* the existing OWN-001 use-of-moved branch). Read
   `__init_<vname>`. If 0 AND `__init_seen_<vname>` is 1 (distinguishes
   from absent keys) AND state != 2 AND not a parameter → emit
   INIT-G11-READ-BEFORE-INIT at error severity. Returns immediately so
   OWN-001 doesn't double-fire.

6. **Branch-merge intersection in `own_merge_moved`** (line ~19398).
   Extended to handle `__init_*` keys via intersection: post-join init
   state = (then-state init AND else-state init). The legacy "if
   either arm has value 2 → mark moved" path stays unchanged for
   `__os_*` state keys. The `__init_seen_*` sentinel is excluded from
   the intersection (always 1 once set; its role is gating, not flow).

The init flag is per-fn (lives on the `own` env, reset per
`check_fn`). Per-name (no alias tracking — Phase 3 territory).

## Honesty

- The `as` cast (kind 99) in check_expr does NOT recurse into its
  inner expression. So `return x as i32;` doesn't read `x` through
  check_expr, and INIT-G11 won't fire on that shape. The brief's
  spec is "any read of a slot whose init-state is not definitely
  assigned"; the kind-99 path should arguably trigger but it
  currently doesn't. Same kind-99 walk-gap likely affects OWN-001
  and Q3's cond-moved check too — out of scope for this Q. Filing
  as a follow-up item per the brief's "name partial-state delta"
  rule rather than silently deferring. Real adopter idiom of
  `let mut x: T;` typically returns x directly, not via cast, so
  the gap is small but documented.
- Aliased reads (`let w = x;` then read w) aren't tracked. Same
  alias deferral as Q2/Q3 — Phase 3 territory.
- Loops not yet handled: a loop body that initializes a binding on
  some iterations only would slip past the DA pass because the loop
  walker doesn't snapshot+merge per iteration. Phase 3 territory;
  brief's specific examples are if/else.
