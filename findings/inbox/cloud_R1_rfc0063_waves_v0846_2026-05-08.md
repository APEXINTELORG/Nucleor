## Filter discipline (s1-only helper deps)

Many wave-13 candidates couldn't be moved because their s1 bodies
reference helpers that exist ONLY in s1 (`tok_name`, `tok_pos_at`,
`node_set_span`, `parse_bitwise`, `str_eq_at_len`,
`diag_emit_text_with_source`, `posix_drive_to_windows`, `source_find`,
`run_external_tool`, plus 412 other s1-only fns). Pre-flight scan:
extract candidate body, scan for `\bidentifier\(` patterns, drop if any
identifier is in the s1-only set. This filter excluded ~50 candidates
across waves 13a/13b/13c without ever touching the build.

## Drift-protected exclusions (must stay LOCAL in tools_suite)

`tools/check_compiler_drift.sh` reads these by source-file presence
(does not follow imports). Moving them broke the drift gate — restored:

| fn | drift gate it serves |
|---|---|
| `get_rt_name` | runtime-helper name table parity |
| `is_ptr_ret` | ptr-return ABI parity |

| `emit_externs` | LLVM `declare` block parity |
| `emit_user_externs` | LLVM `declare ` sb_append parity (1 entry) |
| `compiler_version_label` | CLI version-string drift gate |

Plus `match_bind_payloads_typed` (paired with SIG_DIFFERS
`match_bind_payloads`; can't move one without the other).

These 7 are filed as Phase B residuals — the proper fix is teaching the
drift script to follow imports (out of scope for R1, which can't touch
`tools/`).
