### Blockers / dependencies

- **B1 — Cross-module import of unit aliases:** Phase 4 (alias rods) requires importing rod-defined unit IDs into the parser's known-alias table. The current `import "stdlib/rods/units.nr"` exposes runtime IDs, not parser-known aliases. Phase 1 must establish the parser's known-alias table before Phase 4 can cleanly populate it. **Status: pre-existing architectural constraint, not a new blocker.**
- **B2 — Polynomial encoding width:** RFC-0005 §3.1 uses integer exponents; RFC-0005 PHASE-PLAN §Phase 1 uses `Vec<i32>`; RFC-0047 uses `[i8; 7]`. Recommend aligning on `Vec<i32>` length-7 for Phase 1 substrate (avoids overflow on intermediate `dim_poly_scale`), then exposing an `[i8; 7]` view for stable wire format if codegen needs it. **Status: design choice, not a blocker.**
- **B3 — Rational exponents for `sqrt(unit<T, A>)`:** RFC-0005 §3.1 supports `unit<T, A> ^ N` (literal `N`) and `sqrt(unit<T, A>)` requiring rational exponents. Phase 1 plan uses integer-only `Vec<i32>`. RFC-0005 §6.1 recommends `Rational<i32>`. **Recommendation: defer rational support to a Phase 6 (post-launch). v1.0 ships integer exponents only; sqrt(unit<T, A>) is a fail-closed compile-time error until Phase 6.**
- **B4 — `radian` dimension stance:** RFC-0005 §6.2 notes ISO 80000 vs SI disagreement. Recommend SI-aligned dimensionless `rad` with optional compiler warning when `m + rad` (existing TYP-003 covers the strict mismatch case). **Status: design choice, not a blocker.**
- **B5 — Currency units (`USD`, `EUR`):** RFC-0005 §6.3 declares out of scope. **Status: confirmed out of scope; do not let any phase fixture introduce them.**
- **B6 — Memory budget alignment with self-host:** PHASE-PLAN §"Coordination notes" states 770 MB self-host cap is unchanged. Phase 1 polynomial helpers add no per-call overhead (type-check time only). **Status: no new memory regression expected; perf gate must still run on Phase 1 ship per the standard rule.**

There are NO hard blockers — every open item has a clean phase ship with the existing PHASE-PLAN. The only design choices flagged (B2–B5) are recommendations to lock before Phase 1 starts, not blockers.

## 7-vector lowering note

Per RFC-0047 §Implementation: dim vectors are purely type-level; runtime sees only the bare T. Phase 1 substrate (`Vec<i32>` length-7) IS the 7-vector lowering at the type-check level. Codegen strips units (RFC-0005 §4 row "Codegen | Strip units (zero runtime cost) | ~30 LOC"). No separate lowering pass needed beyond Phase 1's polynomial helpers + Phase 2's emit sites.

## Literal suffix note

RFC-0047 §Design enumerates `_kg, _m, _s, _N, _J, _W, _Pa, _Hz, ...` plus SI prefixes (`_mm`, `_km`, `_us`, `_GHz`). RFC-0005 §3.2 enumerates `value{unit_expr}` form (e.g., `10.0{m}`). Both forms are useful; the `value{unit_expr}` form is more general (any expression, parsed verbatim), the underscore-suffix form is more ergonomic for the common case.

**Recommendation: ship `value{unit_expr}` first (Phase 1), defer underscore-suffix to a Phase 1.5 lex extension once the alias table from Phase 4 is available.** Stage-gating the suffix form on the alias table avoids hardcoding the suffix ↔ dim-vector map in the lexer.
