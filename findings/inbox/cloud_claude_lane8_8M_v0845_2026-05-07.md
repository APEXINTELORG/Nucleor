# Cloud Lane 8 / Queue 8M — partner Lane 1 / Queue 1B Wave 11 rebase

## Summary

The partner branch `fix/partner-rfc0063-tools-suite-wave11-v0845`
(commit `49576c98`) was based on `5890c84` (pre-Wave-10) and produced
git conflicts when cherry-picked onto current `origin/main` (post
`c1eea2e9` which already retired Wave 10's helpers). The conflict is
**structural-but-resolvable** — Wave 10 (in main) and Wave 11 (in the
partner branch) target **disjoint sets of helpers**, so the resolution
is to take the union of both deletion sets in `nucleor_tools_suite.nr`
and the union of both helper-bundle additions in
`nucleor_rfc0063_shared_wave1.nr`, plus a doc-narrative merge and a
fresh CSV regeneration.

This is **not** an "overlapping deletion" case (the 8M escape clause):
neither branch tries to delete any helper the other one keeps. Wave 10
retired 18 byte-identical accessor helpers; Wave 11 retires 13 reviewed
allocation-shape constructor helpers. Zero name collision between the
two sets.

## Resolution applied

1. **`compiler/nucleor_tools_suite.nr`** — deleted the 13 Wave 11
   helpers from their HEAD positions (line 61 for `tok_new`, lines
   283-293 for `mk2`-`mk6` / `mk_list` / `pr`, lines 1551-1576 for the
   five `ir_*` helpers). HEAD's existing structure (extern decls,
   `expect_tok`, `parse_args`, `ir_select`, `ir_fn_new`, etc.)
   preserved unchanged.

2. **`compiler/nucleor_rfc0063_shared_wave1.nr`** — appended the partner's
   13 `#[manual_drop]` helper definitions at the end of the file, after
   the existing Wave 10 batch (lines 2829+). Each Wave 11 helper uses
   `Vec::with_capacity(<exact count>)` per the partner's reviewed
   allocation-shape lift.

   merge: 2.0.3a now reads "after v0845 Wave 10 Queue 1A + Wave 11 Queue

   Wave 11 explicitly noted as the `Vec::new() → Vec::with_capacity(...)`
