# Migrating from Nucleor v0.1.x to v0.2.0 (and beyond)

Released 2026-04-22. Companion to [`docs/milestones/v0.2.0.md`](../milestones/v0.2.0.md)
and the [v0.2.0 CHANGELOG entry](../../CHANGELOG.md).

This guide covers v0.1.x → v0.2.0 plus the v0.2.x stdlib enrichment
chain (v0.2.18 through v0.2.38). The enrichment chain is **strictly
additive**: every release between v0.2.0 and v0.2.38 preserved the
v0.2.0 surface and added new helpers + examples without changing any
existing semantics.

## TL;DR for upgraders

**v0.2.0 is fully backwards-compatible with v0.1.x source.** Every
v0.1.x program that built green continues to build green under
v0.2.x; the v0.1→v0.2 deltas are additive (new builtins, new CLI
subcommands, new diagnostic warnings) plus one behavior change
(warnings no longer halt the build, see "Diagnostics" below).

The two optional migration steps below let you adopt the new syntax;
the legacy syntax keeps working through the entire v0.x line.

**v0.2.0 → v0.2.38 is also fully additive.** The 18 incremental
v0.2.x releases shipped 75+ new runtime helpers (math, fs, env, time,
path, parse/stringify, padding, hashmap, statistics, random,
checked-arithmetic) and 5 end-to-end demo programs — none of them
change any existing v0.2.0 behavior. See
"v0.2.18..v0.2.30 stdlib enrichment" below for the complete table.

## Migration step 1 — switch to `use std::*` import syntax

v0.2.0 adds Rust-style import paths. The legacy quoted form still
works:

```nr
import "stdlib/rods/atomic.nr"   // v0.1.x — still works in v0.2
use std::atomic;                  // v0.2 — preferred new syntax
```

The migration tool rewrites every legacy import in a file in one
shot:

```
$ nuc fix --imports src/main.nr
nuc fix --imports: rewrote 3 import line(s) in src/main.nr
```

Repeat for each `.nr` in your project. Verified across all 11
example programs (see CHANGELOG v0.1.65) — every one builds green
after the rewrite.

Path mappings:

| Legacy quoted | v0.2 `use` form |
|---|---|
| `import "stdlib/rods/atomic.nr"` | `use std::atomic;` |
| `import "stdlib/rods/foo/bar.nr"` | `use std::foo::bar;` |
| `import "./helper.nr"` | `use crate::helper;` (or `mod helper;`) |
| `import "../shared.nr"` | `use super::shared;` |

## Migration step 2 — adopt `?` for error propagation

v0.1.x error handling required hand-written `if result_is_err(r)`
checks:

```nr
fn divide_chain(a: i64, b: i64, c: i64) -> Vec<i32> {
    let r1: Vec<i32> = divide(a, b);
    if result_is_err(r1) == 1 { return r1; };
    let q1: i64 = result_unwrap(r1);

    let r2: Vec<i32> = divide(q1, c);
    if result_is_err(r2) == 1 { return r2; };
    let q2: i64 = result_unwrap(r2);

    return result_ok(q2);
}
```

v0.2 ships the `?` postfix operator (RFC-0016 phase 1):

```nr
fn divide_chain(a: i64, b: i64, c: i64) -> Vec<i32> {
    let q1: i64 = divide(a, b)?;        // propagates Err
    let q2: i64 = divide(q1, c)?;
    return result_ok(q2);
}
```

`?` works after any primary expression, field access, index, or
inside binops (`maybe(a)? + maybe(b)?`).

Note: until generic enums land (RFC-0024 in v0.4), `?` propagates
the error verbatim — there is no `From<E>::from` conversion. The
function's return type and the inner expression's error type must
match.

## New language features (no migration required)

These are new in v0.2 — adopt at your pace.

- **`as` cast operator** (RFC-0015 phase 2): `let x: i64 = (y as
  u32) as i64;`. NUM-003 warns when a cast loses precision (e.g.
  `i64 as i8`); the warning does not block compilation.
- **`mod foo;`** (RFC-0018 phase 1): single-line `mod` declaration
  loads `./foo.nr` at preprocess time. Block-form
  `mod foo { ... }` arrives in v0.4.
- **`if let` / `while let` sugar** (RFC-0016 phase 1): both desugar
  to a `match` with a wildcard arm.
- **`..=` inclusive range** (RFC-0023 partial): for-loop iteration
  with inclusive upper bound: `for i in 0..=10 { ... }`.
- **`#[test]` / `assert_eq!` / `assert_ne!`** (RFC-0021): write
  tests inline in source, run with `nuc test path/to/file.nr`.
  Pair with `--isolation=process` to spawn a fresh child per test.
- **stdin read primitives**: `read_line()`, `read_i64()`,
  `read_byte()` (RFC-0015 phase 4).

## New CLI subcommands

| Command | Purpose |
|---|---|
| `nuc fix --imports <file>` | Rewrite quoted imports to `use std::*` |
| `nuc fix --numeric <file>` | Lint mixed-width arithmetic, suggest `as` casts |
| `nuc doc <file> [--out f.md]` | Emit Markdown reference from `///` doc comments |
| `nuc lock [manifest]` | Write `Nucleor.lock` from `[dependencies]` |
| `nuc install <pkg>` | Add a path or registry dependency |
| `nuc publish [manifest]` | Copy package into a local registry |
| `nuc registry list \| search \| versions \| verify` | Local registry inspection |
| `nuc test --isolation=process` | Per-test process isolation (RFC-0021 phase 2) |

Run `nuc help` for the complete list.

## New comprehensive runtime helpers

All callable directly from any Nucleor source — no `use` required.
The v0.2.0 release shipped the foundational set; the v0.2.18..v0.2.30
enrichment chain layered on substantial additional surface (see
`docs/rfcs/HELPER-CONTRACT.md` for the full inventory).

### v0.2.0 foundational helpers

- **Math primitives**: `i64_abs/min/max/clamp/sign/pow/isqrt/gcd/lcm`,
  `f64_sin/cos/tan/asin/acos/atan/atan2/sinh/cosh/tanh/exp/exp2/log/

  is_nan/is_inf/is_finite`, constants `f64_pi/tau/e/sqrt2/ln2/ln10`,

  `wrapping_*`/`saturating_*`/`checked_*` × `add/sub/mul` × `i8/i16/
  i32/i64/u8/u16/u32/u64`. Read the failure flag with
  `checked_overflow_flag()`.
- **Atomic primitives**: `atomic_i64_new/free/load/store/fetch_add/
  fetch_sub/fetch_and/fetch_or/fetch_xor/swap/cas` (cross-platform

- **Process spawn**: `proc_run`, `proc_capture_stdout`,

- **Cryptographic + serialization**: SHA-256, CRC32, Base64,
  UUID v4, MessagePack subset, BE/LE byte buffer R/W.

## Diagnostics

- **Behavior change:** warnings no longer halt the build (v0.1.x
  bailed at exit code 1 on any diagnostic). Errors still halt;
  warnings flow through the report and compilation continues. If
  your CI treats `nuc build` exit code as the source of truth, this
  is strictly more permissive.
- **JSON output:** `nuc check --json` now emits machine-readable
  diagnostics (RFC-0020 phase 2).
- **`nuc explain`** documents 38 error codes across the NR / RT /
  MATCH / COLL / MOD / PKG / TGT / EFF / LAW / UNIT / CONTRACT /
  ATOMIC / ISR / WCET / DEPTH / NUM series.

## Package manager

`nuc.toml` is now the canonical project manifest (RFC-0019 phase 1).
Schema:

```toml
[package]
name = "my_app"
version = "0.1.0"
entry = "src/main.nr"

[dependencies]
util = "libs/util"     # path dep — relative to manifest dir

[workspace]
members = ["libs/util", "libs/core"]   # optional
```

Run `nuc lock` to generate `Nucleor.lock`. The lockfile records every
package's checksum and dependency graph for reproducible builds.

Registry-backed `[dependencies]` (with PubGrub resolver + git
sources) lands in v0.5.

## Cross-platform

- **POSIX `nuc` wrapper** (`./nuc`) ships in v0.2 — resolves clang
  via `NUCLEOR_CLANG_PATH` / `LLVM_SYS_180_PREFIX` / standard distro
  paths and execs `bin/nucleor`.
- The Linux/macOS native `bin/nucleor` build lands in v0.3 — the
  Windows binary continues to be the only pre-built artifact in
  v0.2.
