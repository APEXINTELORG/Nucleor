# Migrating from Nucleor v0.2.x to v0.4.0 (and beyond)

Released 2026-04-30. Companion to [`docs/milestones/v0.4.0.md`](../milestones/v0.4.0.md)
and the [v0.4.x CHANGELOG entries](../../CHANGELOG.md). v0.3 was an
intermediate cross-platform release tracked in
[`v0.3.0.md`](../milestones/v0.3.0.md); this guide covers v0.2 → v0.4
end-to-end (v0.3 deltas are folded in where adopter-relevant).

## TL;DR for upgraders

**v0.4 source mostly compiles unchanged from v0.2** — but the v0.4
diagnostic tightening means several silent-miscompute patterns from
v0.2 now halt at compile time with a clean error. If your v0.2 build
emitted no warnings AND your runtime tests passed, you're almost
certainly clean. If it relied on any of the patterns listed in
"Adopter-impact errors" below, you need to add a fix.

There are no syntax changes you must make. The new features
(rich pattern matching, doc generator polish, saturating-per-op
arithmetic, etc.) are opt-in.

## What's new — high-impact features

### Rich pattern matching (RFC-0023)
- **Range patterns:** `1..=9`, `1..10`, half-open `0..` / `..b`.
- **Or-patterns** with int literals + wildcards: `1 | 2 | 3 => "small"`.
- **Pattern guards:** `match x { n if n > 0 => ..., _ => ... }`.
- **`@`-bindings:** `match x { n @ 1..=10 => use(n), _ => 0 }`.
- **Slice patterns:** `[a, .., b]`, `[single]`, `[]`.
- **Struct destructuring:** `Point { x, y } => x + y`, plus enum
  or-patterns with same-name bindings: `Sign::Pos(n) | Sign::Neg(n) => n`.
- **Field-equality literal patterns** (`Point { x: 0 } => ...`)
  remain deferred to v0.5+. The v0.4.163 ship made them halt with
  MATCH-012 instead of crashing the compiler with an ACCESS VIOLATION.
  Express the same intent today with a guard:
  `Point { x, y } if x == 0 && y == 0 => ...`.

### Saturating + wrapping + unsafe arithmetic blocks
```nucleor
let s: i32 = saturating { 2147483647 + 100 };   // → i32::MAX (no wrap)
let w: i32 = wrapping    { 2147483647 + 1 };    // → i32::MIN (two's-complement wrap)
let u: i32 = unsafe      { /* skip overflow checks */ };
```
The `saturating` block lowers each inner arithmetic op to a saturating
intrinsic (so multi-step expressions don't overflow at the i64 level
before the final clamp). The `wrapping` block is a passthrough on
Nucleor's i64 ABI (which already wraps); it's there to make intent
explicit and to forward-compatibly support a future overflow-checked
default mode.

### `nuc doc` polish (RFC-0029)
- **Per-parameter rendering:** `**Parameters:**` bulleted list per fn.
- **Per-return rendering:** `**Returns:** \`<type>\``.
- **Module-level docs:** `//!` lines at the file head become the
  document intro paragraph(s).
- **Struct + Enum indexes:** dedicated sections alongside the
  Function index.
- **Markdown + HTML modes:** `nuc doc <file>` (markdown), or
  `nuc doc <file> --html` / `nuc doc <file> --out X.html` (HTML
  with anchor links + minimal inline CSS, single-file output).

### Closures + concurrency primitives
- Closure literals (`let f: i64 = |x| x * 2;`) and direct calls.
- Higher-order fns taking closures as i64-typed callable params
  (`fn apply(f: i64, x: i64) -> i64 { return f(x); }`).
- `conc_spawn`, `conc_mutex`, `channel_new`, `thread_spawn`, etc.
  in `stdlib/rods/concurrency.nr`.

### Generic trait bounds at call sites (TYP-025)
v0.4.162 closed a silent miscompute where `add_values<T: Addable>(...)`
silently accepted concrete types that didn't have an `impl Addable for T`
in scope. Now the call site halts with TYP-025.

## Adopter-impact errors (newly-rejected v0.2 patterns)

If your v0.2 code triggered any of the silent-miscompute patterns
below, v0.4 will halt at compile time. Each diagnostic includes a
remediation hint inline; the table here just shows the shape.

| Diagnostic | What now halts |
|---|---|
| **TYP-014** | calling a non-callable typed binding: `let s: str = "x"; s(42);` |
| **TYP-016** | `let x: i32 = if cond { 5 };` — if-expression assigned to non-void without an `else` |
| **TYP-021** | `let x = void_returning_fn();` — void RHS in let |
| **TYP-022** | bare struct name in value position: `let v = MyStruct;` (use `MyStruct {}`); also `MyStruct(42)` for non-tuple-struct |
| **TYP-023** | chained method on void receiver: `void_fn().method()` |
| **TYP-024** | `if cond { 1 } else { "two" }` — incompatible branch types |
| **TYP-025** | `f(arg)` where `f<T: Trait>(...)` and `arg`'s type doesn't `impl Trait` |
| **NUM-022** | int vs float in a binop: `5 < 5.0` (was silent `false`) |
| **NUM-023** | float / bool runtime miscompute (URGENT — was a SIGSEGV class) |
| **MATCH-011** | heterogeneous match arm types (was silent SIGSEGV class) |
| **MATCH-012** | struct pattern with field-equality literal (was a compiler ACCESS VIOLATION) |
| **OWN-001** | String use-after-move on binding transfer |

The full list of v0.4.x diagnostic ships is in `CHANGELOG.md`
under the v0.4.135–v0.4.165 entries. Each entry shows a 5–10
line repro and the remediation.

### TYP-014 narrowing in v0.4.164

v0.4.122 added i*/u* to TYP-014's "uncallable types" list — but
Nucleor's pre-RFC-0025 ABI uses i64 for both numeric values
**and** function pointers, so legitimate code using i64-as-fn-ptr
(closures bound to i64, fn-ptr params) started halting incorrectly.
v0.4.164 dropped i*/u* from the list. The remaining narrow gap —
`let n: i64 = 5; n(x);` typoing a numeric variable as a fn — returns
to pre-v0.4.122 runtime SIGSEGV with no compile-time signal. This
will be fully closed when proper fn-pointer types ship in RFC-0025.

If your v0.2-to-v0.4-rc1 build was halted by TYP-014 on closure or
fn-ptr-in-i64 code, **pull v0.4.164+ and rebuild** — it should now
compile clean.

## Performance + memory

The v0.4 compiler self-builds in **~3 seconds cold / ~0.9 seconds
hot** with a peak RSS of ~131 MB. The locked baseline targets are
6.54s cold / 0.88s hot / 502 MB peak (with +10% drift ceilings).
Adopters' codebases will see proportional improvements vs v0.2 on
the ownership-pass tightening (v0.3.221 own_put fast path), the
sym table fast path (v0.3.222), and the `str_substring` revert
that closed the v0.3.205 13× perf killer (full story in
`docs/migrations/v0.1-to-v0.2.md` "Perf history").

The drift gate (`tools/check_perf_regression.ps1`) is
**mandatory before every ship** — it compares cold + hot self-build
times and peak RSS against the locked baseline. Adopters
maintaining a fork should run it on each release candidate to catch
the same regression class that bit v0.3.205.

The runtime e-stop wrapper (`tools/run_capped.ps1`) caps process
RSS at 1 GB hard kill, real-time. Wrap any potentially-runaway
build, probe, or compile step in it.

## Diagnostics taxonomy

v0.4 firms up the diagnostic-code namespace per RFC-0020:

| Family | What it covers |
|---|---|
| **TYP-NNN** | type-check errors (010, 011, 014, 016, 021–025) |
| **NUM-NNN** | numeric semantics (008, 018, 020, 022, 023) |
| **MATCH-NNN** | match-expr / pattern errors (003–006, 008–012) |
| **OWN-NNN** | ownership / borrow errors (001) |
| **NR-NNN** | parser / lexer fall-through (NR020 catch-all is being de-emphasized; replacements emit class-specific codes) |
| **RT-NNN** | runtime helper preconditions (RT-005, RT-007, RT-008) |

Every code that fires has an entry in `nuc explain <code>` (the
explain registry is drift-gate enforced — adding a code without
the entry fails the gate).

## Tooling additions

- `nuc doc <file> [--html] [--out <path>]` — Markdown + HTML doc
  generator (RFC-0029). Now emits Parameters + Returns + Struct/Enum
  indexes + module-level `//!` intros.
- `nuc fix --numeric` — migration linter for the v0.1→v0.2
  numeric type-lattice tightening (RFC-0015).
- `tools/run_capped.ps1` — 1 GB e-stop wrapper for Windows process
  containment.
- `tools/check_perf_regression.ps1` — drift gate (cold + hot
  self-build wall + peak RSS vs locked baseline).
- `tools/gen_helper_manifest.py`, `tools/gen_rod_manifest.py` —
  manifest generators (drift-gate enforced).

## Operating model — probe + fix dual-agent split (2026-04-30)

The Nucleor_OSS repo runs a dual-agent operating model documented
in `PARALLEL_AGENT_PROBE_MANDATE.md` and `SELF_HANDOFF.md`. It does
not affect adopters — it's repo-internal — but if you're forking
Nucleor and want to mirror the discipline, the two key artifacts
are:
- **`findings/inbox/` + `findings/promoted/`** — the bug-report
  inbox/archive surface (probe agent drops, ships, moves on
  completion). Lives outside `tests/` so verify-suite cost is zero.
- **The two-tier resource policy** (`tools/run_capped.ps1` for
  e-stop, `tools/perf_baseline.json` + `check_perf_regression.ps1`
  for drift) with the no-compound rule (drift is fixed against the
  locked baseline, not the previous run; never `-Update` baseline
  to absorb a regression).
