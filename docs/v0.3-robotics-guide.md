# Nucleor v0.3 — Robotics RT Guide

> **Audience:** writing real-time control loops in Nucleor (PID,
> motor control, sensor fusion, deadline-bound state machines).
> **Status:** every attribute and diagnostic listed here is wired
> end-to-end as of v0.3.17 with v1 source-level enforcement, smoke
> coverage, and verify-gate steps.

The v0.3.x ship arc landed RFC-0001 in full plus the extern-C
shim generator. This guide collects everything in one place so
you can read a single page and start writing real-time-correct
Nucleor today.

## TL;DR — the L1 hard real-time bundle

```nucleor
#[no_alloc]
#[no_panic]
#[no_dyn]
#[deadline = 100]
fn pid_step_rt(kp: i64, ki: i64, kd: i64,
               err: i64, integral: i64, last_err: i64) -> i64 {
    let derivative: i64 = err - last_err;
    let p_term: i64 = kp * err;
    let i_term: i64 = ki * (integral + err);
    let d_term: i64 = kd * derivative;
    return p_term + i_term + d_term;
}
```

Compile-time guarantees this fn body:

- Allocates nothing on the heap (`#[no_alloc]` -> RT-001).
- Has no panic-prone calls (`#[no_panic]` -> RT-002).
- Uses no dynamic dispatch (`#[no_dyn]` -> RT-003).
- Comes in under 100 microseconds wall-clock (`#[deadline = 100]`
  -> RT-004 runtime + static estimator).

The full worked example lives at
[`examples/19_rt_pid.nr`](../examples/19_rt_pid.nr).

## Attribute reference

| Attribute              | Purpose                                          | Diagnostic |
|------------------------|--------------------------------------------------|------------|
| `#[no_alloc]`          | Forbid heap allocation in this fn body           | RT-001     |
| `#[no_panic]`          | Forbid panic-prone calls (`unwrap`, `assert`, …) | RT-002     |
| `#[no_dyn]`            | Forbid dynamic dispatch (`dyn Trait`, `Box<dyn>`)| RT-003     |
| `#[deadline = N]`      | Wall-clock budget in microseconds                | RT-004     |
| `#[max_depth = N]`     | Bound recursion in a `#[deadline]` fn            | (opts out RT-008) |
| `#[allow(<CODE>)]`     | Suppress one diagnostic file-wide                | (filter)   |
| `#[deny(<CODE>)]`      | Promote a warning to an error file-wide          | (promote)  |
| `#[export]`            | Make a fn callable from C via `nuc gen-headers`  | (codegen)  |
| `#[repr(C)]` (struct)  | C-ABI-compatible struct layout                   | (codegen)  |

## Diagnostic reference (RFC-0001 §3.5)

Every code from the spec table now has v1 source-level
enforcement, smoke coverage, and (where applicable) a negative
fixture.

| Code   | Severity | Fires when                                                              | Shipped |
|--------|----------|-------------------------------------------------------------------------|---------|
| RT-001 | error    | `#[no_alloc]` fn body calls an alloc-prone builtin                      | v0.2    |
| RT-002 | error    | `#[no_panic]` fn body calls a panic-prone builtin                       | v0.3.1  |
| RT-003 | error    | `#[no_dyn]` fn signature/body uses `dyn`                                | v0.3.5  |
| RT-004 | warning + abort | Static WCET estimate exceeds budget; runtime overrun aborts        | v0.3.0 + v0.3.2 |
| RT-005 | warning  | RT-marked fn calls an `extern fn` (FFI is opaque)                       | v0.3.8  |
| RT-006 | error    | RT attribute attached to an `async fn`                                  | v0.3.7  |
| RT-007 | warning  | `#[deadline]` without `#[no_alloc]` or `#[no_panic]`                    | v0.3.3  |
| RT-008 | warning  | Direct self-recursion in `#[deadline]` fn lacks `#[max_depth]`          | v0.3.9  |

All warnings are suppressible per-file via `#[allow(RT-NNN)]`.
Errors are not suppressible by design.

## extern-C interop

`nuc gen-headers` walks the source for three kinds of
declarations and emits a matching C header:

- `extern fn name(...) -> ret;` — fn declared in C, called from
  Nucleor (the import direction).
- `#[repr(C)] struct Name { ... }` — struct usable across the
  ABI boundary in either direction.
- `#[export] fn name(...) -> ret { ... }` — fn defined in
  Nucleor, callable from C through the unmangled LLVM symbol
  (the export direction; v0.3.4).

```bash
nuc gen-headers tests/fixtures/t34_export.nr -o nucleor_kernel.h
# nuc gen-headers: wrote 1 #[repr(C)] struct(s),
#                  1 extern decl(s),
#                  3 #[export] decl(s) to nucleor_kernel.h
```

The host C/C++ build then `#include "nucleor_kernel.h"` and
links against the Nucleor-built `.o` directly — no FFI wrapper
hand-rolling required.

## v1 limitations and what's deferred to v0.4

The v0.3.x checks are deliberately source-level v1
implementations. Each is a substring/text-walk over the
post-resolver source, with the strip pass from v0.3.6 masking
out string literals and `//` comments before scanning. This is
fast, predictable, and fails-safe in the same direction
(false positives, suppressible) — but it's not an AST
analyzer. The known v1 limitations:

- **RT-001/002/003 string-literal escapes** — fixed by the
  v0.3.6 strip pass. A forbidden token inside `"..."` no longer
  false-triggers; doc strings explaining what's banned are safe.
- **RT-005 ffi-no-* annotation** — not yet shipped. v1 fires on
  every extern call from an RT body; `#[allow(RT-005)]`
  suppresses per-file. v0.4 will introduce
  `#[ffi_no_alloc, ffi_no_panic]` markers on the `extern fn`
  declaration so trusted FFI symbols can opt out individually.
- **RT-008 indirect recursion** — only direct self-recursion
  fires today (v0.3.9 walks the post-resolver inner body for
  the wrapper's own name). Mutual recursion (A → B → A) needs
  a call graph and is left for the v0.4 AST-based check.
- **RT-004 static WCET v1 estimator** — coarse multiplier ladder
  (no whiles → ×1, 1 → ×100, 2 → ×1000, 3+ → ×10000) capped at
  10⁶ units. Designed to flag obviously-wrong budgets at compile
  time without producing precision noise. v0.4 introduces an
  AST-based v2 estimator that tightens the bounds.

## Self-host fixed-point invariant

Every commit that touches `compiler/nucleor_s1_compiler.nr`
preserves the two-iteration LLVM IR fixed point:

```bash
nuc build compiler/nucleor_s1_compiler.nr -o stage_b
cp target/stage_b.exe bin/nucleor.exe
nuc build compiler/nucleor_s1_compiler.nr -o stage_c
nuc build compiler/nucleor_s1_compiler.nr -o stage_d
diff target/stage_c.ll target/stage_d.ll  # must be byte-identical
```

The verify gate's "self-host bootstrap fixpoint" step
(currently 358/385) enforces this on every release. If you
contribute a compiler change that breaks the fixed point, the
gate will block the merge.
