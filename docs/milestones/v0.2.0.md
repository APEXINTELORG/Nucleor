## Helper Schema Deliverable (Helpers.md contract — added 2026-04-22 in v0.2.33)

A two-phase cataloging deliverable scoped against the helper surface
the v0.2.x stdlib enrichment chain produced. Per the user's
`Helpers.md` contract, this is **echo-before-acting**: Phase 1
(taxonomy report — chat-only, no file writes) gates Phase 2
(population of `docs/rfcs/helper_manifest.toml` +
`helper_manifest_schema.md`). Currently Phase 1 echo is on the
record; awaiting "go" before the walk starts.

Full deliverable spec lives in `docs/milestones/v0.4.0.md` — that
tracker is the long-lived home; it's referenced here because the
**going-forward constraint** kicks in immediately:

> Any helper added to the codebase from v0.2.33 onward MUST also
> add a row to `helper_manifest.toml` in the same commit. Drift
> gate enforcement lands once Phase 2 is approved.

So even though the manifest itself is a v0.4 deliverable, the
behavioral constraint on new commits applies starting now.
