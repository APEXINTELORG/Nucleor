### Part 2 — Content-addressed compilation cache

Forward-design item from `docs/milestones/v0.5.0.md`. The `incremental: source cache hit (fast)` path that exists today is content-addressed only by mtime + size — fragile across rebuilds.

Build a real one:

1. **Cache key:** SHA-256 of `(source content || compiler-version-string || build-flags-canonical)`. Compiler version comes from `--version` output. Build flags canonicalized to a sorted list (so flag-order doesn't invalidate).
2. **Cache storage:** `target/.nuc_cache_v2/<sha-prefix>/<sha>.ll` plus a `meta.json` per entry with input filename, build-flags string, compiler version, and timestamp.
3. **Cache lookup:** `nuc build foo.nr` computes key, looks up `target/.nuc_cache_v2/<key>.ll`, on hit copies the `.ll` to the requested output path with `cache: hit (sha=<prefix>)` printed; on miss runs the full pipeline and stores result with `cache: miss → stored (sha=<prefix>)`.
4. **Cache invalidation:** any source content change → new sha → automatic miss. No timestamp races. Manual eviction via `nuc clean --cache`.
5. **CLI flag:** `--no-cache` already exists; respect it. New flag `--cache-stats` prints hit/miss counters for the current build.
6. **Hit/miss accounting in build output:** every build prints one line `cache: <state> (key prefix, size N MB)`.

**Fixture:**

- `tests/features/cache_v2_round_trip.nr` — build a fixture twice; second build reports `cache: hit`.
- `tests/features/cache_v2_invalidation.nr` — touch the source file (no content change) → still `hit`. Modify content by one char → `miss`. Both via the cache_v2 path.

**Acceptance:**

- Cache-cold and cache-warm timings in the artifact (warm should be much faster — measure it).
- Two-stage fixed-point on the compiler with cache enabled and disabled (results must match).
- Full verify gate: any test that uses `--no-cache` still passes; tests without `--no-cache` get cache benefit but still pass.
- Edge case: rebuilding compiler itself with cache enabled. Caches its own intermediate `.ll`; second self-build reports hits everywhere.

**Artifact:** `docs/milestones/spikes/track_l_perf_cache_2026-04-30.md` — perf baseline numbers, cache key design, hit-rate measurements (typical adopter workflow %), invalidation correctness proof, future content-storage growth estimates.
