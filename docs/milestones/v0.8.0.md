# v0.8.0 Milestone Tracker

**Target:** 2028-Q1
**Theme:** Stabilization, ABI freeze, safety-cert pilot
**Status (2026-04-24):** Planning

## Theme

v0.8.0 is the **stabilization** milestone. The language and
stdlib have been growing through v0.2-v0.7; v0.8 is the freeze:
no new features, only bug fixes, and a public commitment to
backward compatibility from this point forward.

After v0.8 ships, the path to v1.0 is one or two more cycles
of audit + ABI signing.

## Cross-cutting workstreams

### ABI freeze

- [ ] Stable C ABI for every `__nucleor_*` runtime symbol
- [ ] Versioned symbol table; old binaries find new runtimes
      via versioned `__nucleor_v1_*` aliases
- [ ] `nuc abi diff` reports any ABI-relevant change between
      two builds; CI gate fails on accidental break
- [ ] Public ABI documentation page

#### ML expansion ABI scope (2026-05-01)

Per `Desktop\Nucleor_Build_Spine\03_TRIAGE\ML_EXPANSION_SET_INTEGRATION_2026-05-01.md` §2 v0.8 list, the v0.8 ABI freeze must cover the runtime symbols required by the four substrate slices that landed v0.5 → v0.7. This makes the "old binaries find new runtimes" story load-bearing for adopters who shipped models or tabular pipelines on intermediate cuts.

**Required symbol coverage:**

| Slice | Symbol family | Source milestone |
|---|---|---|
| Model serving | `__nucleor_serve_*` (KV cache, prefill/decode, batching, mmap, telemetry hooks) | v0.6 Lanes E + F + G |
| Backend dispatch | `__nucleor_backend_dispatch`, `__nucleor_backend_select`, `__nucleor_backend_accounting_*` | v0.6 Lane J |
| Table interop | `__nucleor_arrow_*` (C Data Interface bridge), `__nucleor_dlpack_*` (RFC-0010), `__nucleor_table_schema_*`, `__nucleor_external_borrow_count` | v0.7 Lane H |
| Capsule verification | `__nucleor_ncap_verify_*`, `__nucleor_ncap_signature_*`, `__nucleor_schema_manifest_digest_*` | v0.5 RFC-0031 + v0.7 conformance |

**Acceptance:** `nuc abi diff` against the v0.8.0 manifest reports zero changes for any symbol in the four families above. The CI gate fails the build if any new commit removes, renames, or changes the calling convention of any covered symbol.

### Safety-cert pilot

Take one real safety-critical project (UAV flight controller,
robot-arm safety supervisor, medical infusion pump) all the
way through `nuc build --profile=cert` (introduced v0.7) and
produce the IEC 61508 / ISO 26262 certification artifact bundle:

- [ ] Architecture description (auto-generated from RFC chain)
- [ ] Hazard analysis tied to specific `#[require]` / `#[ensure]`
      contracts
- [ ] WCET evidence per safety-classified fn (RFC-0009)
- [ ] Test coverage report tied to MC/DC criterion
- [ ] Build provenance + signed binary

#### ML expansion perf gates (2026-05-01)

Per the integration crosswalk §2 v0.8 list, v0.8 perf gates must include **model-serving + tabular workloads** with **backend accounting populated** in the bench/profiler output:

- [ ] `nuc bench` includes a model-serving workload (per the v0.6 Lanes E + F + G shape — GGUF or safetensors prefill/decode loop) with regression bound vs the v0.7 baseline
- [ ] `nuc bench` includes a tabular workload (Lane H schema + pushdown + backend dispatch round-trip) with regression bound vs the v0.7 baseline
- [ ] Profiler output (`nuc bench --profile`) carries the **backend accounting block** (op → backend chosen → fallback reason → cycles spent in each backend) for both workloads
- [ ] Conformance report (`nuc bench --report=conformance`, introduced v0.7) survives the v0.8 ABI-freeze cycle bit-exact when run against the same `.ncap` artifacts
