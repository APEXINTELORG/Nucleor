## Typed dimensional units (RFC-0005)

`unit<T, dim>` where `dim` is a compile-time-checked dimension
expression (e.g. `length`, `length/time`, `mass·length²/time²`
for energy). The compiler enforces dimensional correctness on
arithmetic — adding meters to seconds is a compile error;
multiplying meters by seconds yields `unit<f64, length·time>`.

This is the type-system overlay for the existing 17 CODATA 2018
constants + SI conversion functions (already shipped in v0.1
via `physics.nr`). v0.6 makes them dimensionally enforced.

Mars Climate Orbiter: `nuc mco` already explains why this
matters; v0.6 is the prevention.

| Phase | Item |
|---|---|
| 1 | Dimension expression syntax + parser |
| 2 | Type-system propagation through `+`, `-`, `*`, `/`, `^` |
| 3 | Diagnostic `UNIT-001..006` family |
| 4 | Migrate `physics.nr` constants to dimensioned form |
| 5 | Migrate `linalg.nr` operations to preserve dimension |

## `#[isr]` interrupt service routine (RFC-0008)

`#[isr]` attribute marks a fn as eligible for use as a hardware
interrupt service routine. Composes with v0.3 `#[no_alloc]` +
v0.5 `#[max_depth]` + the runtime tier system. Fn must:

- Have `void(void)` signature (no args, no return)
- Be `#[no_alloc]`
- Be `#[max_depth = N]` for some N
- Optionally `#[deadline = T]` (RFC-0001 v0.3)
- Compile to a sequence with no `call` to non-`#[isr]`-eligible fns

| Phase | Item |
|---|---|
| 1 | `#[isr]` attribute parsing + signature check |
| 2 | Composition checker: `#[isr]` implies the above set |
| 3 | Linker-section directive (`.text.isr`) for the embedded
      flash layout |
| 4 | Vector-table glue: `#[isr_vector(IRQ_NUM)]` registers the fn |

## Embedded-target sysroots

Concrete embedded targets supported as build targets:

- ARM Cortex-M (M0+, M3, M4F, M7) via `arm-none-eabi`
- RISC-V 32-bit (rv32imac) via `riscv32-none-elf`
- ESP32 (Xtensa) via `xtensa-esp32-elf`

Each gets a sysroot with stripped libc (newlib-nano) and a
linker script template.

### Lane E — Hugging Face frontend (local model package metadata)

Source: `HUGGINGFACE_RUNTIME_SPEC.md`.

**v0.6 substrate work** (NOT a Hugging Face replacement):

- Local model directory contract — `.ncap` accepts safetensors-
  formatted weight folders with tokenizer/config/weight metadata
- Safetensors requirement flag
- Local-files-only policy (no remote fetching from `nuc serve`)
- Zero Python runtime accounting — `nuc serve model.ncap` runs
  without invoking `python.exe` or `pip install`

**Acceptance evidence:** deterministic local smoke fixture loads
a safetensors-format weight folder + tokenizer/config metadata
through `.ncap`; no Python interpreter spawned during the run.

### Lane F — ONNX / GGUF interchange

Source: `ONNX_GGUF_RUNTIME_SPEC.md`.

**Rule:** real GGUF or safetensors loader ships FIRST, then ONNX.
Manifest-only evidence is separate from native execution proof.

**v0.6 substrate work:**

- **GGUF manifest fields:** architecture, tensor count, metadata,
  quantization families, tokenizer fields, context window, mmap
  regions, KV-cache contracts
- **ONNX manifest fields:** opset, inputs, outputs, initializers,
  nodes, shape contracts, dtype policies, unsupported ops,
  execution providers
- External runtime / loader accounting — `nuc bench` reports which
  loader ran and what version

**Acceptance evidence:** GGUF manifest parsing fixtures pass; first
GGUF model loads + runs end-to-end; ONNX loader rejects unsupported
opsets with clear diag (NOT silent miscompute).

### Lane G — vLLM serving contract

Source: `VLLM_RUNTIME_SPEC.md`.

**Rule:** distinguish "OpenAI-compatible production server" from
first serving MVP. Require deterministic local smoke before any
public serving claim.

**v0.6 substrate work** (`nuc serve model.ncap`):

- Scheduler policy (FIFO MVP; priority queues + admission control
  are post-v0.6)
- KV-cache policy (block-paged attention layout per the spec)
- Max active sequences + max batched tokens
- Block size / count config
- Prefill / decode routes
- Paged-attention contract count reported in `nuc bench`
- External runtime accounting (which serving backend executed)

**Acceptance evidence:** deterministic-local-serving smoke fixture
runs end-to-end; backend accounting populated; OpenAI-compatibility
note in the README distinguishes "MVP" from "production".

### Lane I — Boosting runtime (flagship-app input)

Source: `BOOSTING_RUNTIME_SPEC.md`.

**Rule:** core Nucleor does NOT own the whole boosting library.
Use as **flagship app / benchmark input** once model import + table
substrate exist.

**v0.6 substrate work:**

- Fitted tree ensemble scoring fixture (load XGBoost / LightGBM /
  CatBoost output, score)
- Missing-value routing
- Multiclass softmax output
- Model import boundary (clear diag if model file unsupported,
  not silent miscompute)
- Backend dispatch accounting

**Acceptance evidence:** flagship-app demo loads + scores a
fitted XGBoost / LightGBM / CatBoost model; backend dispatch
accounted in `nuc bench` output. ML Suite owns the training
library — Nucleor owns the inference + import boundary.

### Lane J — Kernel backend runtime (CRITICAL for Lane A claims)

Source: `KERNEL_BACKEND_RUNTIME_SPEC.md`.

**Substrate fields** that must populate in every `nuc bench` output:

- backend manifest (which backends compiled in)
- active backend field (which one ran THIS bench)
- device field (CPU model / GPU model)
- external backend count
- scalar fallback count
- CPU / GPU backend count
- fused kernel count
- zero Python runtime flag

**Tier A backend targets** (v0.6 commits at least 2 of these
shipping clean):

- Nucleor scalar + shape-specialized generated kernels (always
  available, baseline)
- OpenBLAS / BLIS (CPU)
- oneDNN (CPU + integrated graphics)
- cuBLAS / cuDNN (NVIDIA GPU)
- GGML or llama.cpp-compatible kernels (LLM serving path)

**Spine action:** keep MLIR / IREE full architecture under later
SOTA / RFC-0036 path (v1.0). v0.6 ships the dispatch contract
+ accounting; v1.0 ships the MLIR pipeline.

**Acceptance evidence:** backend manifest emitted on every
`nuc bench`; Tier-A backend dispatch demonstrated for at least
one math rod (`linalg`, `stats`, or `kdt` are the v0.5 candidates).
