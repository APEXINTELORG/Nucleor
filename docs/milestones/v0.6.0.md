## Typed dimensional units (RFC-0005)

`unit<T, dim>` where `dim` is a compile-time-checked dimension
expression (e.g. `length`, `length/time`, `mass·length²/time²`
for energy). The compiler enforces dimensional correctness on
arithmetic — adding meters to seconds is a compile error;
multiplying meters by seconds yields `unit<f64, length·time>`.

This is the type-system overlay for the existing 17 CODATA 2018
constants + SI conversion functions (already shipped in v0.1
via `physics.nr`). v0.6 makes them dimensionally enforced.

Mars Climate Orbiter: `nuc mco` already explains why this
matters; v0.6 is the prevention.

| Phase | Item |
|---|---|
| 1 | Dimension expression syntax + parser |
| 2 | Type-system propagation through `+`, `-`, `*`, `/`, `^` |
| 3 | Diagnostic `UNIT-001..006` family |
| 4 | Migrate `physics.nr` constants to dimensioned form |
| 5 | Migrate `linalg.nr` operations to preserve dimension |

## `#[isr]` interrupt service routine (RFC-0008)

`#[isr]` attribute marks a fn as eligible for use as a hardware
interrupt service routine. Composes with v0.3 `#[no_alloc]` +
v0.5 `#[max_depth]` + the runtime tier system. Fn must:

- Have `void(void)` signature (no args, no return)
- Be `#[no_alloc]`
- Be `#[max_depth = N]` for some N
- Optionally `#[deadline = T]` (RFC-0001 v0.3)
- Compile to a sequence with no `call` to non-`#[isr]`-eligible fns

| Phase | Item |
|---|---|
| 1 | `#[isr]` attribute parsing + signature check |
| 2 | Composition checker: `#[isr]` implies the above set |
| 3 | Linker-section directive (`.text.isr`) for the embedded
      flash layout |
| 4 | Vector-table glue: `#[isr_vector(IRQ_NUM)]` registers the fn |

## Embedded-target sysroots

Concrete embedded targets supported as build targets:

- ARM Cortex-M (M0+, M3, M4F, M7) via `arm-none-eabi`
- RISC-V 32-bit (rv32imac) via `riscv32-none-elf`
- ESP32 (Xtensa) via `xtensa-esp32-elf`

Each gets a sysroot with stripped libc (newlib-nano) and a
linker script template.
