# v0.5 Residual Sequencing — 2026-04-30

Companion to `docs/milestones/v0.5.0.md`. Breaks each v0.4 residual
into focused sub-ships with risk/effort/value scoring. Picks the
**first ship** for each residual. Updates as ships land.

## Scoring rubric

- **Risk:** L (mechanical refactor) / M (touches hot path or
  multiple subsystems) / H (touches bootstrap / ABI / cross-cutting
  invariants).
- **Effort:** XS (1 ship, < 100 lines) / S (1 ship, 100-300 lines)
  / M (2-3 ships) / L (4+ ships).
- **Value:** L (cleanup / symmetry) / M (visible improvement) /
  H (unblocks other work or fixes class of bugs).

## Residual 1: RFC-0015 phase 3c — typed fn params + call-site type info

**Status:** REVERTED v0.4.224. Bootstrap regression on i32 params
abused by `str_from_int(n: i32)`. Needs call-site type-info
propagation.

**Sub-ship plan:**

1. **3c.1: cross-width-arg detection at call site.** [Risk M /
   Effort S / Value H] Add a type-check pass that walks each kind-7
   call. For each arg, compare arg's type to the callee's declared
   param type (looked up via sigs). If arg width > param width
   (i64 → i32 narrowing), record at the call site. Emit a NEW
   diag NUM-NNN warning (or pass-through-quiet for now) so we can
   audit the surface BEFORE shipping any silent narrowing.
2. **3c.2: explicit `as` cast injection at call boundary.** [Risk H
   / Effort M / Value H] At lower_expr kind-7 call site, when 3c.1
   detected cross-width, emit `__nucleor_as_<param_type>(arg)`
   BEFORE passing to the call. With explicit narrowing at the
   boundary, the callee can safely trunc-on-entry.
3. **3c.3: re-enable typed param alloca.** [Risk M / Effort S /
   Value M] Restore v0.4.221's `lower_fn` param-typing edits.
   With 3c.2 in place, narrow params arrive already-narrow; trunc-
   on-entry is a no-op for in-range values. Self-build verifies.
4. **3c.4: comprehensive fixture.** [Risk L / Effort XS / Value M]
   Extend `tests/features/rfc0015_phase3_widths_full.nr` with
   cross-width call patterns; new self-build-bootstrap fixture.

**First ship:** 3c.1 — surface-audit pass. Doesn't change codegen,
just emits warnings on detected cross-width. Adopters can review
and migrate before 3c.2 changes runtime behavior.

## Residual 2: RFC-0015 phase 3e — strict-mode default flip

**Status:** DEFERRED. v0.3.220 perf rationale: 8.5× regression with
helper-call dispatch.

**Sub-ship plan:**

1. **3e.1: LLVM overflow intrinsic substrate.** [Risk M / Effort S
   / Value H] Add ir_inst ops for `add_with_overflow` /
   `sub_with_overflow` / `mul_with_overflow`. Emit
   `call {iN, i1} @llvm.sadd.with.overflow.iN(...)` +
   `extractvalue` + branch-on-flag. Wire as opt-in via env var
   first.
2. **3e.2: panic block emit.** [Risk L / Effort S / Value M] On
   overflow flag set, emit `call void @__nucleor_panic_overflow(...)`.
   Reuse existing panic helper.
3. **3e.3: strict-mode default flip.** [Risk M / Effort XS / Value
   H] Flip `NUCLEOR_INT_STRICT_ARITH=1` default. Verify gate +
   self-build perf (target: under 1.13s hot ceiling — should be
   safe without helper-call cost).
4. **3e.4: opt-out mechanism.** [Risk L / Effort XS / Value L]
   `NUCLEOR_INT_STRICT_ARITH=0` falls back to LLVM `add nsw` (silent
   wrap, current default behavior).

**First ship:** 3e.1 — wire the overflow-intrinsic op codes +
emit. Strict-mode stays opt-in; new opt-in path uses intrinsics
instead of helpers. Measure perf delta vs current opt-in helper
path to validate the +infrastructure investment.

## Residual 3: RFC-0015 phase 3b cmp/shift/bitwise narrow IR

**Status:** Low-priority symmetry. i64 path functionally correct.

**Sub-ship plan:**

1. **3b-cmp.1: signed narrow cmp.** [Risk M / Effort S / Value L]
   Extend `lower_expr` kind-4 cmp dispatch (ops 7-12) to detect
   same-narrow-width signed (i8/i16/i32) operands and emit
   `icmp <pred> iN`. Result is i1; zext to i64 at chain exit.
   Unsigned narrow types fall through to i64 path.
2. **3b-cmp.2: unsigned narrow cmp.** [Risk M / Effort S / Value L]
   Add unsigned predicate dispatch (ult/ugt/ule/uge) for u8/u16/u32
   operands. Requires emit_cmp variant that takes a "signedness"
   flag.
3. **3b-shift.1: narrow shift.** [Risk L / Effort S / Value L]
   `shl iN` / `lshr iN` (unsigned) / `ashr iN` (signed) for narrow
   LHS. Shift amount stays i64-stored, trunc'd to iN at emit.
4. **3b-bitwise.1: narrow bitwise.** [Risk L / Effort XS / Value L]
   `and iN` / `or iN` / `xor iN` for same-narrow operands. Native
   LLVM, no signedness concern.

**First ship:** Skip for v0.5 unless there's adopter pull. The i64
path is functionally correct; this is purely IR-shape symmetry.
Reconsider if profiling shows narrow-cmp-heavy code in adopter
benchmarks.

## Residual 4: RFC-0020 phase 3 — span-metadata-through-AST

**Status:** ~26 find_in_source/find_linecol_in_source sites. Linemap
infrastructure already exists (RFC-0020 phase 1). Need AST-node
span integration.

**Sub-ship plan:**

1. **3span.1: parallel spans Vec.** [Risk M / Effort M / Value H]
   Add a parallel `Vec<i32>` keyed by AST nid. Add `node_set_span`
   / `node_get_span` helpers. Threading through parse: each `mk*`
   call site immediately calls `node_set_span` with the byte
   offset. ~118 mk* sites in parse but mechanical.
2. **3span.2: high-impact diag site migration.** [Risk L / Effort
   S / Value M] Pick 5-7 most-frequent diag sites. Replace
   `find_linecol_in_source(source, fn_name, var_name)` with
   `linemap_line/col(linemap, node_get_span(pool, nid))`. Verify
   diagnostic output matches prior format.
3. **3span.3: full migration.** [Risk M / Effort M / Value M]
   Migrate remaining 19+ diag sites. Drop find_in_source family
   helpers (or keep as fallback for nodes with span=0).
4. **3span.4: span-aware diag rendering.** [Risk L / Effort S /
   Value H] Use spans for `^^^^` underline rendering — Rust-style
   carets that point at the actual source character range, not
   just the line. RFC-0020 phase 1's renderer already supports
   col; extend for end-col via span-end tracking.

**First ship:** 3span.1 — substrate. Parallel spans Vec + threading.
Doesn't change diagnostic output yet, but unlocks 3span.2-4. Verify
gate must stay green; T1.7 fixed-point will need re-locking.

## Suggested v0.5 ship order (first 8 ships)

1. **3c.1** — cross-width call-site audit (warnings only, no
   codegen change). Low risk, high learning value.
2. **3span.1** — span Vec substrate. Foundation for all diag work.
3. **3span.2** — high-impact diag sites migrated to spans.
4. **3e.1** — LLVM overflow-intrinsic substrate (opt-in only).
5. **3c.2** — `as` cast injection at call sites where 3c.1 found
   cross-width.
6. **3c.3** — re-enable typed param alloca on top of 3c.2.
7. **3span.3** — finish diag migration, drop find_in_source.
8. **3e.3** — flip strict-mode default; verify perf.

After ship 8, all four v0.4 residuals are landed. v0.5 substantive
work (RFC-0006 DbC, RFC-0007 atomics, etc.) begins from ship 9+.

## Out-of-scope for v0.5 residual closeout

- Phase 3b cmp/shift/bitwise narrow IR — unless adopter benchmark
  shows real perf signal. Defer to v0.6 if not.
- Signature ABI change to typed-iN — phase 3c keeps i64 ABI. Full
  iN signature is a separate substantial ship, v0.6+.

**Liskov design choice (v0.4.257):** count-based, not predicate-
equality. If impl req_count > trait → CONTRACT-004; impl
ens_count < trait → CONTRACT-005. False negatives possible
(predicates differ semantically with same count) but never
false positives. Full predicate-implication check requires the
same SAT/SMT substrate as CONTRACT-007 cert proof — deferred
as a single research-grade ship.

**Per-fn opt-out caveat (v0.4.258):** `#[no_check]` covers
require + ensure; invariants attach to `impl` blocks not fns
so per-method invariant opt-out requires splitting into a
separate `impl Type { ... }` block without the `#[invariant]`
attribute. Documented as a workaround.
