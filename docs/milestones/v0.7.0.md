## Static WCET (RFC-0009)

`#[deadline = T]` (RFC-0001 v0.3) currently sets a soft target
checked at runtime via per-iteration cycle counters. v0.7
upgrades this with **static** WCET (worst-case execution time)
analysis via the Heptane open-source toolchain.

| Phase | Item |
|---|---|
| 1 | Heptane bridge: emit annotated assembly that Heptane reads |
| 2 | `nuc wcet` CLI: report WCET per fn |
| 3 | Compile error if `#[deadline = T]` fn's WCET > T |
| 4 | Per-target cost models (Cortex-M3, M4F, M7, RV32IMAC) |
| 5 | Loop-bound annotations: `#[loop_max(N)]` so Heptane has
      enough info to bound iteration counts |

This is the key feature for safety-critical certification work
(IEC 61508, DO-178C, ISO 26262). The cert-mode build profile
(introduced in RFC-0006 v0.5) requires WCET proof for any
`#[deadline]` fn.

## DLPack tensor interchange (RFC-0010)

Zero-copy tensor handoff to / from PyTorch, JAX, NumPy, TVM,
TensorFlow via the DLPack standard. Existing `tensor_nd.nr` and
`tensor_decomp.nr` rods become DLPack-source / DLPack-sink with
no data copy.

| Phase | Item |
|---|---|
| 1 | DLPack header (`dlpack.h`) bundled in runtime |
| 2 | `tensor_to_dlpack()` / `tensor_from_dlpack()` rod helpers |
| 3 | Integration test with PyTorch via `nuc-cxx` (RFC-0011 v0.4) |
| 4 | Stride / device-type / dtype mapping table |
| 5 | Error path for incompatible dtype / device |

Once DLPack lands, Nucleor's full numerical stack (autodiff,
linalg, FFT, ODE) becomes callable from any major ML framework
with zero serialization cost.

## Certified-build profile

`nuc build --profile=cert` enforces a strict superset of safety
guarantees:

- All `#[deadline]` fns have static WCET proven (RFC-0009)
- All contracts (`#[require]`, `#[ensure]`, `#[invariant]`) have
  static proof or explicit `#[unverified]` annotation
- No `#[allow]` for safety-cert error codes (NUM-*, OWN-*, RT-*)
- No `panic!` reachable from `#[no_panic]` paths
- Build manifest hash + LLVM IR hash signed for audit trail

## ML expansion — Lane H substrate (2026-05-01)

Source: `Desktop\Nucleor_Build_Spine\03_TRIAGE\ML_EXPANSION_SET_INTEGRATION_2026-05-01.md` §1 Lane H (Tabular Engine Substrate) and §2 v0.7 add-or-strengthen list.

The ML Suite expansion brief identifies **table-engine substrate** items that the core compiler/runtime owns — the dataframe library itself stays in ML Suite, but the zero-copy interop, schema accounting, and backend dispatch hooks that make it work at-pace land here. v0.7 is the right milestone because DLPack (RFC-0010) is already in flight and Arrow shares the same buffer-protocol structural pattern.

### Substrate items (Lane H)

| Phase | Item | Notes |
|---|---|---|
| 1 | **Arrow C Data Interface bridge** — `arrow_array_to_buffer` / `arrow_buffer_to_array` runtime helpers; ABIv1 schema struct emitted with C ABI guarantees | mirrors DLPack RFC-0010 phase-2 helper shape; reuses dlpack-side stride/dtype mapping |
| 2 | **Schema manifest** — table-of-tables manifest format on `.ncap` artifacts (column name, logical type, physical layout, null bitmap presence, dictionary-encoded flag) | gates the regulated-artifact flagship app's column-by-column reproducibility evidence |
| 3 | **Zero-copy buffer accounting** — runtime counter for `external_borrow_count` (buffers held by foreign DLPack/Arrow consumers); `nuc bench` and `nuc serve` report it in their summary block | fed by `external backend count` field already proposed for Lane J |
| 4 | **Pushdown flag set** — public enum `PushdownKind { ProjectionOnly, FilterOnly, ProjectionAndFilter, Aggregation, None }` exposed via the table-engine boundary so plan callers can advertise capability | required by Polars-style lazy plans built on top in ML Suite |
| 5 | **Backend dispatch accounting hook** — `__nucleor_backend_dispatch` shim records (op, backend chosen, fallback reason) into a ring buffer; `nuc bench --backends` dumps a histogram | aligns with Lane J substrate landing in v0.6 |

These five items are the **core substrate** Lane H needs. The dataframe library, lazy-plan optimizer, SQL frontend, and pushdown-capable kernels stay in ML Suite per the brief's lane-ownership rule.

### Acceptance evidence

- DLPack round-trip with Arrow consumer (PyArrow): zero `memcpy` calls in the buffer transfer path under `--profile=zero-copy-strict`
- Schema manifest survives `.ncap` sign + verify cycle (RFC-0031); column type info recoverable bit-exact
- `external_borrow_count` non-zero across a tabular-engine smoke fixture; drops to zero after consumer drops the DLPack capsule
- ML Suite tabular-engine integration test passes against this v0.7 substrate without patching core

## Conformance reports

`nuc bench --report=conformance` emits a structured report with:

- backend dispatch table (op → chosen backend → fallback count)
- zero-copy borrow accounting (peak / current / dropped)
- WCET measurements vs `#[deadline]` targets per fn
- contract evidence (which `#[require]` / `#[ensure]` were proven static, runtime-checked, or `#[unverified]`)
- schema-manifest digest for every `.ncap` artifact loaded

This is the artifact that goes into the regulated-artifact flagship's evidence bundle.
