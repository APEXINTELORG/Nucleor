## Inheritance from v0.2.0

and are this milestone's starting backlog. Each line cites the

| Phase | Item | Foundation in v0.2 |

### RFC-0016 (Result/Option/match) v0.4 follow-on

| Phase | Item | Foundation in v0.2 |
|---|---|---|
| 4 | `From` / `Into` trait + auto-conversion in `?` | `?` propagates verbatim through Result stub (v0.1.50) |
| 5 | Diagnostics MATCH-003..006 fired by typecker | MATCH-001/002 firing live (v0.1.61); explain entries documented (v0.1.49) |

Both blocked on RFC-0024 generic enums — the existing untyped
`Result` (Vec<i32> [tag, payload]) is enough for the v0.2 `?`
operator. v0.4 generic enums replace the stub with `Result<T,E>` /
`Option<T>` and unlock From/Into.

### RFC-0018 (modules) v0.4 follow-on

| Phase | Item | Foundation in v0.2 |
|---|---|---|
| 2 | Resolver: path-to-symbol with visibility check | `mod foo;` + `use std::*` desugar (v0.1.52, v0.1.53); `pub` lexed as token 72 |

The v0.2 surface gives users the syntax they expect; v0.4 adds the
symbol-table refactor for proper per-module scoping with `pub`

## Helper Schema Deliverable (Helpers.md contract — added 2026-04-22 in v0.2.33)

A two-phase cataloging deliverable from the user's `Helpers.md`
contract is now a tracked v0.4 deliverable. Phase 1 (taxonomy
report — chat-only, no file writes) gates Phase 2 (population of
`docs/rfcs/helper_manifest.toml` + `helper_manifest_schema.md`).

**Phase 1 — taxonomy report (DONE in v0.2.40):** echo posted in
chat, user approved with "go", taxonomy + counts reported in chat
on 2026-04-22. 14 classes proposed; 7 helpers truly unclassified
and flagged REVIEW REQUIRED in the manifest.

**Phase 2 — manifest population (DONE in v0.2.40):** wrote
`docs/rfcs/helper_manifest.toml` (676 rows, 9674 lines, sorted by
class then name) + `docs/rfcs/helper_manifest_schema.md` (one-page
field reference) via `tools/gen_helper_manifest.py`. The generator
script reads the canonical s1 ABI tables + runtime C source so the
manifest can be regenerated as helpers are added.

144 entries flagged REVIEW REQUIRED at the top of the file:
- 137 declared in IR but no `__nucleor_*` definition found in
  `stdlib/runtime/*.c` (latent linker gaps OR macro-generated
  symbols the regex didn't match).
- 7 truly unclassified entries (name pattern matched no class rule).

**Phase 1 (legacy spec):**
- Walk `compiler/nucleor_s1_compiler.nr`, `compiler/nucleor_tools_suite.nr`,
  and `stdlib/runtime/*.c` to enumerate every helper.
- "Helper" = any callable referenced by symbol from compiler codegen,
  or listed in an ABI table, or implemented as `__nucleor_*` and called
  from generated IR. Stdlib `.nr` rod functions are NOT helpers.
- Produce in chat: total count, proposed taxonomy (only classes
  actually present), count per class, 3 examples per class, and an
  unclassified list.

**Phase 2 — manifest population (only after taxonomy approval):**
- Output: `docs/rfcs/helper_manifest.toml` — one TOML row per helper,
  sorted by class then name.
- Schema (per row):
  `name`, `class`, `symbol`, `dispatch (Inline|RuntimeCall|Intrinsic)`,
  `abi`, `effects[]`, `taint (passthrough|propagates|breaks)`,
  `units (passthrough|carries|strips)`,
  `proof_obligation (none|emits|consumes)`,
  `stability (stable|unstable|experimental)`, `since`, `notes`.
- Also output: `docs/rfcs/helper_manifest_schema.md` — one-page
  field-by-field reference with valid values + worked example.
- Non-obvious policy fields (anything touching certificates, panics,
  alloc, effects, units, taint) MUST be marked `TODO` and the helper
  listed under a `# REVIEW REQUIRED` block at the top.

**Going-forward constraint (added 2026-04-22):**
- Any helper added to the codebase from this point on MUST also add
  a row to `helper_manifest.toml` in the same PR/commit. The drift
  gate (`tools/check_compiler_drift.sh`) will be extended to enforce
  this once Phase 2 lands.
- Any helper *used* in a new example or stdlib path triggers the
  same manifest-row obligation if the helper isn't already cataloged.

**Negative list — Phase 1 and Phase 2 explicitly do not:**
modify any helper implementation, modify any ABI table, rename
anything, merge or de-duplicate apparent redundancies, skip
unclassified helpers (flag them instead), invent policy, or
commit. Working tree stays dirty for human review.

**Success criteria:** every helper in the repo appears exactly
once in `helper_manifest.toml`; every row is fully populated or
flagged `REVIEW REQUIRED`; schema doc page is self-contained;
Phase 1 taxonomy was approved before Phase 2 ran.
