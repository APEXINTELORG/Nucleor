# v0.4.0 Milestone Tracker

**Target:** 2026-Q4
**Theme:** Strict-mode numerics, full module resolver, generic enums, span-migrated diagnostics, language extensions
**Status (2026-04-22):** Planning — populated from v0.2.0 deferrals + Tier-2 RFCs

This is the **canonical sequencing doc** for the v0.4.0 release. The
v0.2 milestone (`v0.2.0.md`) deferred several rows here with explicit
justification — those are this doc's foundation. v0.3 is the
**cross-platform** intermediate release tracked in
[`v0.3.0.md`](v0.3.0.md); v0.4 picks up after v0.3 lands the
Linux/macOS bootstrap. Each RFC has a checklist of milestones; PRs
link back here.

## Inheritance from v0.2.0

### RFC-0015 (numerics) v0.4 follow-on

| Phase | Item | Foundation in v0.2 |
|---|---|---|
| 3 | IR: width-tagged numeric ops | type lattice classifiers (v0.1.62) |
| 3 | Codegen: LLVM type per width | per-width print/arith helpers (v0.1.27, v0.1.54) |

type-lattice classifiers + the linter + the warning-flag are the
v0.2 substrate; flipping the strict-mode switch is one PR plus the
mechanical migration of rod signatures.

### RFC-0016 (Result/Option/match) v0.4 follow-on

| Phase | Item | Foundation in v0.2 |
|---|---|---|
| 4 | `From` / `Into` trait + auto-conversion in `?` | `?` propagates verbatim through Result stub (v0.1.50) |
| 5 | Diagnostics MATCH-003..006 fired by typecker | MATCH-001/002 firing live (v0.1.61); explain entries documented (v0.1.49) |

Both blocked on RFC-0024 generic enums — the existing untyped
`Result` (Vec<i32> [tag, payload]) is enough for the v0.2 `?`

`Option<T>` and unlock From/Into.

### RFC-0018 (modules) v0.4 follow-on

| Phase | Item | Foundation in v0.2 |
|---|---|---|
| 2 | Resolver: path-to-symbol with visibility check | `mod foo;` + `use std::*` desugar (v0.1.52, v0.1.53); `pub` lexed as token 72 |
| 2 | Codegen: name mangling with module path | preprocess-time inlining catches collisions at parse |

The v0.2 surface gives users the syntax they expect; v0.4 adds the
symbol-table refactor for proper per-module scoping with `pub`
enforcement, `pub use` re-export, and `mod foo { ... }` block form.

### RFC-0020 (diagnostics) v0.4 follow-on

| Phase | Item | Foundation in v0.2 |
|---|---|---|
| 3 | Migrate ~80 existing error sites to use spans | `linemap_*` infrastructure (v0.1.59) ready and unused |

## Helper Schema Deliverable (Helpers.md contract — added 2026-04-22 in v0.2.33)

A two-phase cataloging deliverable from the user's `Helpers.md`
contract. Originally tracked here as a v0.4 deliverable; **the
mechanism + 95.1% population shipped in the v0.2.x sub-chain
ahead of v0.4** so this section is now historical.

**Phase 1 — taxonomy report (DONE in v0.2.40):** echo posted in
chat, user approved with "go", taxonomy + counts reported in chat
on 2026-04-22. 13 classes (was originally proposed as 14, then
collapsed during Phase 2 population) covering all 676 helpers.

**Phase 2 — manifest mech (DONE in v0.2.41):** wrote
`docs/rfcs/helper_manifest.toml` (676 rows, sorted by class then
name) + `docs/rfcs/helper_manifest_schema.md` (one-page field
reference) via `tools/gen_helper_manifest.py`. The generator
reads the canonical s1 ABI tables + runtime C source so the
manifest regenerates as helpers are added. Drift-gate enforcement
went live the same release.

**Phase 2 — manifest population (DONE 95.1% in v0.2.73–78):**
643 of 676 rows populated with concrete `effects` / `taint` /
`proof_obligation` values via a 3-level resolution chain
(`NAME_OVERRIDES` → `PATTERN_OVERRIDES` → `CLASS_DEFAULTS`).
Schema vocabulary added the `"sync"` effect tag. Per-class
state table tracked in
[`docs/rfcs/helper_manifest_schema.md`](../rfcs/helper_manifest_schema.md).
The remaining 33 TODO rows are intentional v0.4 placeholders
(TensorOps GPU/CUDA/DLPack/KV-cache forward declarations + 3
ToolingMeta stubs); these will be populated when the
implementations land.

**REVIEW REQUIRED count: 0** as of v0.2.41 (was 144 at the
initial v0.2.40 walk; the v0.2.41 generator + the
`INTENTIONAL_PLACEHOLDER` allowlist resolved the 137 IR-declared-
but-undefined cases by classifying them as deliberate v0.4
forward declarations, and the 7 unclassified cases by extending
`CLASS_RULES`).

**Phase 1 (legacy spec):**
- Walk `compiler/nucleor_s1_compiler.nr`, `compiler/nucleor_tools_suite.nr`,
  and `stdlib/runtime/*.c` to enumerate every helper.
- "Helper" = any callable referenced by symbol from compiler codegen,
  or listed in an ABI table, or implemented as `__nucleor_*` and called
  from generated IR. Stdlib `.nr` rod functions are NOT helpers.
- Produce in chat: total count, proposed taxonomy (only classes
  actually present), count per class, 3 examples per class, and an
  unclassified list.

**Phase 2 — manifest population (only after taxonomy approval):**
- Output: `docs/rfcs/helper_manifest.toml` — one TOML row per helper,
  sorted by class then name.
- Schema (per row):
  `name`, `class`, `symbol`, `dispatch (Inline|RuntimeCall|Intrinsic)`,
  `abi`, `effects[]`, `taint (passthrough|propagates|breaks)`,
  `units (passthrough|carries|strips)`,
  `proof_obligation (none|emits|consumes)`,
  `stability (stable|unstable|experimental)`, `since`, `notes`.
- Also output: `docs/rfcs/helper_manifest_schema.md` — one-page
  field-by-field reference with valid values + worked example.
- Non-obvious policy fields (anything touching certificates, panics,
  alloc, effects, units, taint) MUST be marked `TODO` and the helper
  listed under a `# REVIEW REQUIRED` block at the top.

**Going-forward constraint (added 2026-04-22, drift-enforced
v0.2.41):**
- Any helper added to the codebase from this point on MUST also add
  a row to `helper_manifest.toml` in the same PR/commit. The drift
  gate (`tools/check_compiler_drift.sh`) **enforces this since
  v0.2.41** — adding a new `__nucleor_*` symbol to s1 / runtime /
  tools-suite without re-running the generator fails the verify
  gate's "helper_manifest.toml is up to date" check.
- Any helper *used* in a new example or stdlib path triggers the
  same manifest-row obligation if the helper isn't already cataloged.

**Negative list — Phase 1 and Phase 2 explicitly do not:**
modify any helper implementation, modify any ABI table, rename
anything, merge or de-duplicate apparent redundancies, skip
unclassified helpers (flag them instead), invent policy, or
commit. Working tree stays dirty for human review.

**Success criteria:** every helper in the repo appears exactly
once in `helper_manifest.toml`; every row is fully populated or
flagged `REVIEW REQUIRED`; schema doc page is self-contained;
Phase 1 taxonomy was approved before Phase 2 ran.
