## v0.4 residuals (added 2026-04-30 at v0.4 closeout)

v0.4 closed cleanly with phase 3a/3b/3d shipped + Option-? crash
class fixed (v0.4.225). Four items deferred from v0.4 land here as
v0.5 substantive work, with documented v0.4 rationale and proposed
v0.5 path:

### RFC-0015 phase 3c — typed fn params with call-site type-info

**v0.4 rationale (deferred):** v0.4.221 attempted typed-iN allocas
+ trunc-on-entry for narrow params (i8/i16/i32/u8/u16/u32). Broke
the compiler's own self-build at v0.4.224 because the compiler
abuses Nucleor's i64-everywhere ABI: the lone i32-param fn
`str_from_int(n: i32)` is called with i64 values relying on the
historical alloca-i64-for-all-params behavior. Trunc-on-entry
collapsed `i64::MAX` → `-1`, producing wrong decimal IR for every
large int literal.

**v0.5 path:** call-site type-info propagation. At each call site,
detect when the caller's arg type is wider than the callee's
declared param type. If so, emit explicit `as <param_type>` cast
at the call site BEFORE the call (or panic on overflow if strict-
mode). With explicit casts at the boundary, the callee can safely
trunc-on-entry knowing the value already fits. This makes phase
3c safe for both adopter narrow-typed code AND historical i64-ABI
abuse patterns.

**Acceptance:** v0.4.222's `tests/features/rfc0015_phase3_widths_full.nr`
fixture stays green AND a new self-build-bootstrap fixture passes
(compile compiler with the v0.5 phase 3c, then re-self-build with
the produced bin → both produce byte-identical IR).

### RFC-0015 phase 3e — strict-mode default flip

**v0.4 rationale (deferred):** v0.3.220 documented an 8.5× self-
build perf regression when strict-arith was the default — every
`+`/`-`/`*` routed through panic-on-overflow runtime helpers. The
runtime-call cost dominated the compiler's own arithmetic loops.

**v0.5 path:** LLVM overflow-intrinsic dispatch
(`llvm.sadd.with.overflow.iN` / `llvm.smul.with.overflow.iN`).
These are LLVM-native intrinsics that return `{iN, i1}` — value +
overflow flag — with no function-call overhead. Strict-mode dispatch
becomes:
```llvm
%r = call {i64, i1} @llvm.sadd.with.overflow.i64(i64 %a, i64 %b)
%v = extractvalue {i64, i1} %r, 0
%o = extractvalue {i64, i1} %r, 1
br i1 %o, label %panic, label %ok
```
Branch-on-overflow-flag is fast on x86 (a CMOV / FLAGS check) and
won't compound across the compiler's hot arithmetic. After this
substrate lands, strict-mode-by-default flip is a one-line change.

**Acceptance:** strict-mode default + verify gate green + cold
self-build under cumulative ceiling (currently 3.64s).

### RFC-0015 phase 3b cmp/shift/bitwise narrow IR

**v0.4 rationale (low-priority symmetry):** phase 3b ARITH-COMPLETE
in v0.4.213 covers +/-/*//%. Comparisons (`<`, `==`, etc.), shifts
(`<<`, `>>`), and bitwise (`&`, `|`, `^`) on narrow types still
emit `icmp <pred> i64` / `shl i64` / `and i64` after sext/zext. The
i64 path is functionally correct (sext/zext preserves signed and
unsigned semantics under signed cmp) but cleaner IR is nice for
LLVM optimizer hints.

**v0.5 path:** extend `detect_narrow_chain` to recognize cmp/shift/
bitwise ops in addition to arith. For cmp: emit `icmp <pred> iN`
+ `zext i1 to i64` at chain exit (boolean result still i64 under
the existing ABI). For shift: emit `shl iN` / `lshr iN` / `ashr iN`
based on signedness. For bitwise: native `and iN` / `or iN` /
`xor iN`. Same wrap-correctness story as phase 3b arith.

**Acceptance:** existing `tests/features/rfc0015_phase3_widths_full.nr`
fixture extended with cmp / shift / bitwise cases; all narrow types
× operators × wrap edges green.

### RFC-0020 phase 3 — span-metadata-through-AST migration

**v0.4 rationale (deferred):** the existing diagnostic emit sites
use `find_in_source` / `find_linecol_in_source` to recover line+col
from the source text by name lookup. ~14 emit sites across
ownership / type-check / lower. The migration to
`linemap_line(linemap, span)` requires propagating span metadata
through every AST node — substantive data-flow change touching
parse + every kind dispatcher in lower / type-check.

**v0.5 path:** add a `span: i64` slot to every AST node (mk2/mk3/
mk4/mk5/mk6 constructors). Parse-time records the source byte
offset; linemap maps offsets → (line, col) at diag emit time
(O(log N) binary search instead of O(N) name-substring scan).
Touches ~30 mk* call sites in parse + every diag emit site.

**Acceptance:** all 14 existing find_in_source sites migrated; new
diagnostics emitted with line+col via linemap; verify gate green;
diag-quality fixtures showing precise span markup.

## Design by Contract (RFC-0006)

`#[require(predicate)]` on fn entry, `#[ensure(predicate)]` on fn
exit, `#[invariant(predicate)]` on struct types. Predicates are
arbitrary boolean expressions; checked at runtime by default,
suppressible with `--release` or `--profile=cert` (where the
proof-checker bridge produces a static guarantee).

| Phase | Item |
|---|---|
| 1 | `#[require]` parsing + IR codegen |
| 2 | `#[ensure]` with access to result via `result` keyword |
| 3 | `#[invariant]` on struct types — checked at every public mut |
| 4 | `nuc explain DBC-001..010` for contract violations |
| 5 | Build-profile gate: cert mode rejects unproven contracts |

Builds on RFC-0004 `#[assume(...)]` infrastructure (v0.4) for the
predicate parser.

## Atomics + lock-free queues (RFC-0007)

`#[atomic]` attribute on shared values; SPSC + MPMC lock-free
queue rods backed by C11 `_Atomic` primitives in the runtime.
Foundation for real-time messaging in robotics control loops.

| Phase | Item |
|---|---|
| 1 | C11 atomic primitives in runtime |
| 2 | `#[atomic]` attribute + memory-order parameters |
| 3 | SPSC queue rod (Lamport's algorithm) |
| 4 | MPMC queue rod (Vyukov's algorithm) |
| 5 | Compatibility audit: `#[atomic] + #[no_alloc]` (RT path) |

## `#[max_depth = N]` (RFC-0014)

Bounded recursion attribute. The compiler verifies the call graph
of any fn marked `#[max_depth = 8]` reaches at most 8 deep on any
path; otherwise compile error. Foundation for stack-bounded
real-time systems.

| Phase | Item |
|---|---|
| 1 | Parse + store the bound on the fn signature |
| 2 | Build call graph in the type pass |
| 3 | Cycle detection — `#[max_depth]` on a cyclic fn group must
      have a wrapping argument that proves termination |
| 4 | Diagnostic `RT-008` for depth-bound violation |

## Forward-design items (for v0.9+ implementation, design-only here)

Added 2026-04-29 from the SOTA roadmap analysis (`Nucleor_SOTA_Roadmap_2026-04-29.md`).
These items must be **decided** during v0.5 even though their full
implementation lands later. Deferring the decision creates a v0.6 type-system
migration regret; deciding now means downstream milestones land on
compatible foundations.

### RFC-0033 — Effects in function types (design only)

Promote the existing RT-attribute set (`#[no_alloc]`, `#[no_panic]`,
`#[no_dyn]`, `#[deadline]`, `#[max_depth]`, `#[ffi_no_alloc]`,
`#[ffi_no_panic]`) from out-of-band attributes to part of the
function type itself, surfaced as a `with [...]` clause:

```nr
fn pid_step(err: f64) -> f64 with [no_alloc, no_panic, deadline = 1000]
fn parse(s: str) -> Result<T, E> with [Alloc, Panic]
fn read_config(path: str) -> Config with [Filesystem.readonly("/etc/nucleor")]
```

| Phase | Item |
|---|---|
| 1 | Write RFC-0033 — pin syntax (`with [...]`), reserve grammar slot |
| 2 | Normalize attribute names → effect names (1:1 mapping table) |
| 3 | Declare type-equivalence rule (attribute form is sugar for `with [...]`) |
| 4 | **No codegen change.** v0.5 only writes the spec. |

**Why now:** v0.8 ships futures-based async. If `async fn` lands without
this design pinned, every async signature in the stdlib gets re-touched
at v0.9. Pin the type grammar slot in v0.5 so async lands compatibly.

### RFC-0034 — Compile-time `[]` vs runtime `()` parameters (design only)

Square brackets are *compile-time* values; parentheses are *runtime*
values. Same source, target-specific specialization:

```nr
fn matmul[M: usize, N: usize, K: usize, T: Numeric](a: Tensor<T>, b: Tensor<T>) -> Tensor<T>
```

The `[]` parameters become autotuning + GPU-tile-size + dimension knobs;
this unifies generics, const generics, autotuning, and GPU
specialization into one mechanism (Mojo's design, validated in
SC '25 paper arXiv 2509.21039).

| Phase | Item |
|---|---|
| 1 | Write RFC-0034 — pin `[]` vs `()` grammar |
| 2 | Pin one fixture: `examples/25_compile_time_params.nr` |
| 3 | **No codegen change.** v0.5 only writes the spec. |

**Why now:** v0.6 ships `Tensor<T, Shape, Device>`. Decide before that
lands whether `Shape` is a compile-time `[]` parameter or a runtime
field. Retrofitting the choice in v1.0 breaks every existing tensor call site.

### Content-addressed compilation cache (opportunistic)

Cheap version of Unison's idea. Hash each function's typed AST +
dependencies; cache per-function IR by hash in `target/.nuc_cache/`.

| Phase | Item |
|---|---|
| 1 | `target/.nuc_cache/<hash>.ll` keyed by typed-AST hash |
| 2 | Compiler checks cache before lowering |
| 3 | `NUCLEOR_NO_CACHE=1` env var bypasses |
| 4 | Bootstrap fixed-point invariant becomes a hash chain |

**Why now:** Hot rebuild is 0.83s with 228 rods. With v0.6
(`Tensor<T, Shape, Device>` + kernel backend), v0.7 (cert profile),
and v0.8 (capsules + full URDF) layered on, the rebuild grows.
Build the cache before you need it; pays back across every
subsequent ship including the probe-triage stream.
