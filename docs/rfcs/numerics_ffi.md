# RFC: Numerics — Extern fn ABI + `nuc gen-headers`

## Summary

`extern fn` declarations with narrow types emit correct LLVM
signatures (e.g. `extern fn foo(x: u8) -> i32` → `declare i32
@foo(i8)`). `nuc gen-headers <input.nr>` emits a matching C
header with proper `<stdint.h>` types so external C/C++ projects
can call into Nucleor-compiled libraries through a stable ABI.

## ABI calling convention

The default Nucleor FFI convention is **i64-everywhere**: every
existing `_rt.c` runtime file in `stdlib/runtime/` and
`stdlib/rods/*_rt.c` uses `long long` for parameters and
return values. This is preserved unchanged by T1.1 — every
existing rod continues to work without modification.

Per-extern-fn opt-in: a new `extern fn` declaration may use
narrow types (`u8`, `i32`, `f32`, etc.) and the compiler emits
the corresponding LLVM type in the `declare` statement. Those
types should match the C side's `int8_t` / `uint8_t` / `int32_t`
/ `float` etc.

## Type → C mapping

| Nucleor   | LLVM IR | C (`<stdint.h>`)  |
|-----------|---------|--------------------|
| i8        | i8      | int8_t             |
| i16       | i16     | int16_t            |
| i32       | i32     | int32_t            |
| i64       | i64     | int64_t            |
| isize     | i64     | intptr_t           |
| u8        | i8      | uint8_t            |
| u16       | i16     | uint16_t           |
| u32       | i32     | uint32_t           |
| u64       | i64     | uint64_t           |
| usize     | i64     | uintptr_t          |
| f16       | half    | (no stable C type) |
| bf16      | bfloat  | (no stable C type) |
| f32       | float   | float              |
| f64       | double  | double             |
| bool      | i1      | bool               |
| char      | i32     | uint32_t           |
| ptr       | ptr     | void*              |
| str       | ptr     | const char*        |
| void      | void    | void               |

## `nuc gen-headers` subcommand

```
$ nuc gen-headers stdlib/rods/foo.nr -o foo.h
nuc gen-headers: wrote 12 extern decl(s) to foo.h
```

- Reads the `.nr` source file.
- For each top-level `extern fn NAME(ARGS) -> RTYPE;` line,
  emits a corresponding C declaration.
- Skips extern decls whose argument or return type doesn't
  map to a C type (Vec, generics, etc. — surface diagnostic
  NUM-015 in a future polish phase).
- Default output path: input filename with `.nr` → `.h`
  (`foo.nr` → `foo.h`). Override with `-o <path>`.

### Output template

```c
// Generated by `nuc gen-headers` from foo.nr
// Edits will be lost; regenerate after extern fn changes.
#ifndef NUCLEOR_GEN_HEADERS_H
#define NUCLEOR_GEN_HEADERS_H
#include <stdint.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

int32_t frob(uint8_t x, uint32_t y);
float compute(double a);
void notify(void);

#ifdef __cplusplus
}
#endif
#endif // NUCLEOR_GEN_HEADERS_H
```

## Cross-language linking workflow

1. Write your Nucleor library:
   ```nucleor
   extern fn nuc_compute(input: ptr, n: i32) -> f64;
   fn compute(input: ptr, n: i32) -> f64 { ... }
   ```
2. Generate the header:
   ```sh
   nuc gen-headers mylib.nr -o mylib.h
   ```
3. Build the Nucleor library to a static archive:
   ```sh
   nuc build-shared mylib.nr -o libmylib.a
   ```
4. Link from C/C++:
   ```c
   #include "mylib.h"
   int main() { double r = compute(data, n); return 0; }
   ```
5. ```sh
   gcc main.c libmylib.a -o app
   ```

## Limitations

- **Unsupported types in extern signatures**: Vec<T>, str,
  generics, structs without `#[repr(C)]`. NUM-015 diagnostic
  fires (Phase 10 wired) when an extern decl uses one of these.
- **No header-to-extern reverse direction yet**: import an
  existing C header by hand-writing the matching extern fn
  decls. A `nuc parse-headers` reverse generator is future work.
- **No name-mangling control yet**: extern fn names are
  emitted to LLVM verbatim; no `#[link_name = "alt_name"]`
  attribute.

## Verify-gate test

`tools/verify.ps1` step `nuc gen-headers FFI smoke` generates
a temporary file with mixed-width extern decls, runs gen-headers,
asserts the output contains `uint8_t`, `uint32_t`, `float`, and
`void frob_void(void)`. Catches regressions in the type mapping
or the text scanner.
