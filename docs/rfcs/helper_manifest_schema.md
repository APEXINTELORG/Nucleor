# `helper_manifest.toml` schema

This document is the field-by-field reference for
`docs/rfcs/helper_manifest.toml`. The manifest is the source-of-truth
catalog for every `__nucleor_*` runtime helper the compiler can emit
calls to. Generated by `tools/gen_helper_manifest.py` from the
canonical compiler ABI tables — do not edit the TOML by hand.

## Structure

The file is a flat sequence of `[[helper]]` tables, sorted by
`class` then by `name`. A REVIEW REQUIRED comment block at the top
lists every helper whose row needs human attention before it can be
considered authoritative.

## Per-row fields

Each `[[helper]]` row has the following fields, in order:

### `name` — string
The short Nucleor-source name (no `__nucleor_` prefix). Example:
`vec_mean_f64`. This is what users write in `.nr` source.

### `class` — string
One of the 14 v0.2 taxonomy classes:

| Class | Meaning |
|---|---|
| `PureMath` | Pure deterministic math; no effects, no taint, no allocation. Bit-twiddling, integer/float arithmetic, transcendentals, narrow-width casts. |
| `PanickingArith` | Arithmetic that can fail — divide-by-zero, overflow, panic, trap. Includes `checked_*`, `saturating_*`, `wrapping_*` and `panic_*`. |
| `StringFormat` | String construction, parsing, padding, conversion, char predicates. Includes `format_*`, `str_*`, `string_*`, `int_to_str / hex / bin / oct`, `parse_hex / bin`. |
| `IO` | Effectful — read/write/print, filesystem, env, network, process spawn. Anything that touches the OS. |
| `VectorOps` | `vec_*` batch helpers, plus SIMD lane-wise (`f32x4_*`, `i32x4_*`, `simd_*`). |
| `Collection` | HashMap, HashSet, BTreeMap, BTreeSet, VecDeque, HeapMap. |
| `TensorOps` | Tensor / GPU / CUDA / DLPack / KV-cache helpers. |
| `Concurrency` | Atomics, mutexes, channels, threads, rwlocks, cancel tokens, schedulers, parallel reducers. |
| `Time` | Wall and monotonic clocks, sleep, ISO formatting, calendar decomposition. |
| `DataCodec` | TOML, JSON, CSV, INI, Base64, MessagePack, SHA-256, FNV-1a, MurmurHash3, CRC32, bitwise ops. |
| `Allocation` | Region / arena / capture allocation primitives, `free`, `realloc`. |
| `ToolingMeta` | Diagnostic / profiling / certification / doc-gen helpers used by the `nuc` tool. |
| `Random` | RNG bridges and convenience wrappers (`rng_*`, `random_*`, `vec_shuffle`, `vec_sample`, `random_fill`). |
| `Unclassified` | Name pattern did not match any class rule. Listed under REVIEW REQUIRED at the top. |

### `symbol` — string
The C linker symbol the compiler emits, always
`__nucleor_<something>`. Example: `__nucleor_vec_mean_f64`. This is
what `clang` resolves at link time against the runtime archive.

### `dispatch` — `"Inline" | "RuntimeCall" | "Intrinsic"`
- `RuntimeCall` — the compiler emits an external `call` instruction
  to the symbol, resolved at link time. **The default** for every
  v0.2 helper.
- `Inline` — the compiler inlines the body at every call site.
  None today; reserved for v0.4 once the inliner lands.
- `Intrinsic` — recognized by the optimizer for special handling
  (constant folding, algebraic rewrites, replacement with LLVM
  intrinsics). None today; reserved.

### `abi` — string
The IR-level signature, in the form `(arg_types...) -> ret_type`.
Argument types are in IR notation (`i64`, `ptr`); return type is
likewise. Example: `(ptr) -> i64` for `__nucleor_vec_len`.
`TODO` if the IR `declare` row could not be parsed.

### `effects` — list (or `"TODO"`)
List of effect tags this helper performs. Empty `[]` means pure
(safe under `@hot` / `@const_fn` enforcement). Effect tags include:

- `"alloc"` — calls `malloc` / `calloc` / `realloc`.
- `"io"` — touches stdin / stdout / stderr / file system.
- `"clock"` — reads a wall or monotonic clock.
- `"random"` — reads PRNG state.
- `"net"` — opens or reads from a socket.
- `"thread"` — spawns or joins a thread.
- `"panic"` — may abort the process.

Marked `"TODO"` for everything outside `PureMath` / `VectorOps`
unless the implementation has been verified. **Do not assume `[]`
for unclassified rows.**

### `taint` — `"passthrough" | "propagates" | "breaks"`
Whether taint flowing into the inputs propagates to the outputs.
- `passthrough` — output taint = union of input taint (default for
  pure math / vector batch).
- `propagates` — output taint = input taint plus any internal
  state read.
- `breaks` — output is always considered untainted regardless of
  input. Reserved for verified sanitizers.

Marked `"TODO"` outside `PureMath` / `VectorOps`.

### `units` — `"passthrough" | "carries" | "strips"`
SI / dimensional-units behavior under RFC-0005:
- `passthrough` — unit-typed input flows through to output without
  change. **Default** until v0.6 lands RFC-0005.
- `carries` — output type carries the same unit as the input.
- `strips` — output is dimensionless.

### `proof_obligation` — `"none" | "emits" | "consumes"`
Sage_NS interval / certificate behavior:
- `none` — no proof obligation. **Default** for everything outside
  the certificate emission pipeline.
- `emits` — emits an interval / range certificate as a side effect.
- `consumes` — requires a proof certificate for inputs.

Marked `"TODO"` outside `PureMath` until reviewed.

### `stability` — `"stable" | "unstable" | "experimental"`
- `stable` — defined in `stdlib/runtime/*.c`, callable, and
  exercised by the verify gate.
- `unstable` — implementation may change in v0.4 (no helpers in
  this state today).
- `experimental` — declared in IR but no `__nucleor_*` definition
  found in the runtime tree. **REVIEW REQUIRED** — the compiler
  will emit an unresolved external if these are called from user
  code.

### `since` — string
Version the helper was introduced. Currently set to `"0.1.0"` for
all rows; the v0.2.x enrichment-chain helpers (released v0.2.18
through v0.2.30) will be re-tagged with their actual `since`
release in a follow-up pass, since the `gen_helper_manifest.py`
script doesn't yet know how to map symbols → release.

### `notes` — string
Free text. Used by the generator to record REVIEW REQUIRED reasons:
- `"declared in IR but no __nucleor_* definition found"` — latent
  linker gap.
- `"name pattern did not match any class rule"` — Unclassified.
- (manual edits to add additional context are welcome — they survive
  re-generation as long as they're kept on the `notes = ""` line)

## Worked example

```toml
[[helper]]
name             = "vec_mean_f64"
class            = "VectorOps"
symbol           = "__nucleor_vec_mean_f64"
dispatch         = "RuntimeCall"
abi              = "(ptr) -> i64"
effects          = []
taint            = "passthrough"
units            = "passthrough"
proof_obligation = "none"
stability        = "stable"
since            = "0.1.0"
notes            = ""
```

Reading: `vec_mean_f64` is a vector batch helper, the compiler
emits a runtime call to `__nucleor_vec_mean_f64(ptr) -> i64` (the
return is a packed f64 bit-pattern), it has no observable side
effects, taint flows through unchanged, no SI-unit changes, no
proof obligation, ships in the v0.1 baseline, no warnings.

## Re-generating the manifest

Whenever a helper is added (`get_rt_name` row + IR declare):

```bash
python tools/gen_helper_manifest.py
```

This overwrites `helper_manifest.toml` from the s1 compiler source
of truth. The `tools/check_compiler_drift.sh` gate ensures
`tools_suite` mirrors `s1` for the ABI tables; the manifest reads
only from `s1`.

## Going-forward constraint (v0.2.33+)

Per the Helpers.md contract going-forward constraint, every commit
that adds a new helper MUST also include the regenerated
`helper_manifest.toml`. The drift gate will be extended to enforce
this in a follow-up release.
