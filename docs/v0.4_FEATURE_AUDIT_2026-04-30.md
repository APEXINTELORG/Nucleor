# v0.4 Feature Audit — 2026-04-30

What actually ships in Nucleor v0.4 today (specifically as of v0.4.193),
indexed by RFC. This audit was the result of a full sweep across the
RFC corpus where the Status fields had drifted from shipped reality.
Each entry below was verified live against the v0.4.193 compiler.

This document supersedes any "Draft" or "deferred to v0.4" claims in
individual RFC files where the Status was wrong.

---

## Implemented (audited shipping)

### RFC-0001 — Real-time function attributes
- `#[no_alloc]` — RT-001 fires on `Vec::new()` etc.
- `#[no_panic]` — RT-002 fires on `panic`/`assert_eq`/`unwrap`/etc.
- `#[no_dyn]` — parses + enforces rejection of `dyn` calls
- `#[deadline = <duration>]` — parses (1ms/500us/100ns), advisory
- Composition: `#[no_alloc, no_panic, deadline = 1ms]`

### RFC-0002 — Allocator types (basic)
- `Box<T>` (sugar for `Box<T, Global>`) ships
- `Box::new(value)` lowers + frees on drop

### RFC-0014 — `#[max_depth = N]`
- Both `#[max_depth = N]` and `#[max_depth(N)]` syntaxes parse
- Opts out of RT-008 (recursive `#[deadline]` warning)

### RFC-0016 — Result/Option/match + `?`
- `Result<T, E>` and `Option<T>` user-typed via generic enums
- `match` exhaustive checking
- `?` early return with same-error-type
- `?` auto-conversion via `impl From<X> for Y`
- `TRAIT-001` halts when `?` needs a missing `From` impl

### RFC-0017 — Standard collections
- String, HashMap, BTreeMap, HashSet, BTreeSet, VecDeque all in stdlib
- Full v0.2 DoD met

### RFC-0023 — Rich pattern matching
- Range patterns: `1..=9`, `1..10`, half-open
- Or-patterns: `1 | 2 | 3 | _`
- Pattern guards: `n if n > 0 => ...`
- `@`-bindings: `n @ 1..=10 => n`
- Slice patterns on Vec: `[a, .., b]`, `[single]`, `[]`
- Struct destructuring: `Point { x, y }`
- Same-name enum or-patterns: `Sign::Pos(n) | Sign::Neg(n) => n`

### RFC-0024 — Generics + Iterators (substrate)
- Generic functions: `fn id<T>(x: T) -> T`
- Generic structs: `struct Pair<A, B>`
- Generic enums: `enum Maybe<T> { Some(T), None }`
- Generic-over-generic: `fn unwrap_or<T>(o: Maybe<T>, dflt: T) -> T`
- Bound checking: `TYP-025` fires when bounds don't match call site
- `Vec<i64>` adapter chain via fn-ptrs (`.map`, `.filter`, `.fold`, etc.)

### RFC-0025 — Closures with capture
- Literals: `|x| x * 2`, `|a, b| a + b`, `|| 42`
- Direct calls: `f(args)`
- Capture-by-value: `let m = 10; let f = |x| x * m;`
- Pass through generic higher-order fns

### RFC-0028 — Format strings (Phase 5)
- Type/precision/width/align/zero-pad/radix dispatch shipped v0.4.41
- All everyday format specs: `{:>5}`, `{:.3}`, `{:08x}`, `{:?}`, etc.

### RFC-0029 — `nuc doc` documentation generator
- Markdown + HTML modes (auto-detect from `--out` extension)
- Module-level docs via `//!`
- Per-fn signature, `**Parameters:**`, `**Returns:**` blocks
- Struct + Enum index sections
- Cross-reference links from param/return types to anchors
- `# Examples` / `# Panics` headings inside `///` demoted to H3
- `--test-list` enumerates `nucleor` code blocks per fn

### Probe + Fix agent operating model (v0.4.181)
- `findings/inbox/` → `findings/staged/` → `findings/promoted/` flow
- `CHANGELOG_PROBE_QUEUE.md` for CHANGELOG handoff
- Probe agent on `probe/exploration` proposes; main agent integrates
- 1024 MB e-stop (`tools/run_capped.ps1`); drift gate (baseline+10%)

## Partial (some surface ships, some genuinely deferred)

### RFC-0005 — Typed dimensional units
- **Ships:** `stdlib/rods/units.nr` — named unit IDs + `nuc_unit_convert`
- **Deferred to v0.6+:** the `unit<T, dim>` typed surface,
  UNIT-001..005 emit sites in the type checker

### RFC-0006 — Design by Contract
- **Ships:** `#[require(...)]` / `#[ensure(...)]` / `#[invariant(...)]`
  syntax parses (compiler ignores unknown attributes)
- **Deferred to v0.5.0:** runtime check codegen, REQ-001 / ENS-001 /
  INV-001 diagnostics, invariant-recompute on struct method exit

### RFC-0007 — Atomics
- **Ships:** `stdlib/rods/atomic.nr` — `AtomicI64` ops with
  sequentially-consistent ordering: new/drop/load/store/add/sub/
  and/or/xor/CAS, backed by Win32 Interlocked* + C11 stdatomic
- **Deferred to v0.5.0:** `#[atomic]` attribute, `Atomic<T>` for
  non-i64 widths, Relaxed/Acquire/Release ordering variants,
  SPSC/MPMC lock-free queues

### RFC-0011 — `nuc-cxx` C/C++ FFI codegen
- **Ships:** `nuc gen-headers <file> --out <h>` produces a C header
  skeleton; `extern fn` from `.nr` source flows through to runtime
  FFI (used pervasively in stdlib rods)
- **Deferred:** auto-emission of `pub fn` Nucleor functions as
  C-callable `extern "C"` declarations (`#[export]` parser
  recognition not wired); paired `.nr` + `.h` C++-class-bridge
  codegen

### RFC-0018 — Module system
- **Ships (per RFC status v0.2.x):** `mod foo;` + `use std::*`
  + `pub` token. Opt-in cross-module privatization via
  resolver-layer name-rewriter (T1.5c, v0.2.342) — files with at
  least one `pub fn` get non-pub fns rewritten to `__priv_<file>__`
- **Deferred to v0.4 / v0.5:** full path-to-symbol resolver,
  `pub use` re-export, block-form `mod foo { ... }`

### RFC-0019 — Package manager
- **Ships (per RFC status v0.2.x):** Nucleor.toml manifest,
  Nucleor.lock lockfile, `nuc install`, workspace
- **Deferred to v0.5.0:** registry MVP, PubGrub semver resolver,
  git dependencies, publish/yank

### RFC-0020 — Diagnostics
- **Ships (per RFC status v0.2.x):** LineMap infrastructure, JSON
  output, 158+ explain entries, ANSI color (terminal-detect)
- **Deferred to v0.4:** full span migration of the remaining
  ~14 `find_in_source` legacy sites — substantive AST data-flow
  change to propagate spans through nodes, not mechanical

### RFC-0026 — Trait objects
- **Ships:** Basic `trait` + `impl Trait for Type` declarations,
  static dispatch via `Type::method()`
- **Deferred to v0.5+:** `dyn Trait`, `Box<dyn>`, `&dyn`, vtable
  construction, dynamic dispatch through trait-object pointers

## Genuinely Draft (not implemented)

These have no shipping surface in the v0.4.193 compiler:

- **RFC-0003** — `Pose<F: Frame>` typed coordinate frames
- **RFC-0004** — `#[assume(...)]` proof annotations
- **RFC-0008** — `#[isr]` interrupt service routine attribute
- **RFC-0009** — Static WCET via Heptane integration
  (WCET-001/002 codes reserved in explain registry)
- **RFC-0010** — DLPack tensor interchange
- **RFC-0012** — `nuc-bindgen` libclang-driven binding generator
- **RFC-0013** — URDF-aware compile-time frame chain verification
- **RFC-0015 phase 3** — IR width-tagged numeric ops + per-width
  LLVM types (still emits uniform `i64` — a known silent
  miscompute on i16/u8 print_int falls in this category)
- **RFC-0027** — Explicit lifetime parameters (parser-only;
  borrow checker doesn't enforce)

## Verify gate + perf as of v0.4.193

- **Verify (parallel):** 218 PASS / 1 FAIL (only `runtime/stdin_read`
  which needs interactive TTY, documented baseline)
- **T1.7 fixed-point:** every ship reproduces byte-identical IR
- **Drift gate:** clean throughout the v0.4.x line
- **Perf (cold self-build):** 3.09s (max 3.37s ceiling — baseline +10%)
- **Perf (hot self-build):** 0.89s (max 0.97s ceiling)
- **Peak RSS:** 131 MB (max 144 MB ceiling)

User-stated targets (cold ~6.5s, mem ~500 MB) both comfortably beat.

## How to use this audit

- **Adopters writing v0.4 code:** scan the "Implemented" section
  for what you can use today. Scan "Partial" for what works at
  the ABI/syntax layer but doesn't fully enforce. Avoid "Draft"
  features.
- **Contributors looking for next work:** any "Partial" item with
  a "Deferred to v0.5.0" tag is a candidate v0.5.0 ship. RFC-0015
  phase 3 is the keystone for the remaining 2 v0.4 boxes.
- **Migration from v0.2:** see `docs/migrations/v0.2-to-v0.4.md`
  for the adopter-impact errors table and what changed at the
  diagnostic level.
