# v0.2 — what shipped, what's deferred

Snapshot 2026-04-23, as of tag `v0.2.121`. Source of truth is
[`docs/milestones/v0.2.0.md`](../milestones/v0.2.0.md) +
[`docs/milestones/v0.4.0.md`](../milestones/v0.4.0.md) +
[`CHANGELOG.md`](../../CHANGELOG.md). This doc is the rolled-up
view across **all 141 releases in the `v0.1.46`→`v0.2.121` chain**
(22 v0.1.x preview releases + 121 v0.2.x releases including the
v0.2.0 RC itself, the v0.2.18–v0.2.30 enrichment chain, the
v0.2.41–v0.2.49 manifest-contract chain, and the v0.2.50–v0.2.121
post-RC hardening / Phase 2 population / diagnostic-code coverage
closure sub-chain).

### Post-RC sub-chain (v0.2.50–v0.2.121, 72 releases)

Mostly tooling + doc fixes. The two compiler source changes
in this sub-chain (v0.2.84 `nuc help` doc/fix entries +
v0.2.87 `-V` / `version` aliases) preserved the self-host
LLVM IR fixed point on the standard 2-iteration check.

- **Helper manifest Phase 2 population (v0.2.73–78)** — 643 of
  676 helpers (95.1%) now carry populated `effects` / `taint` /
  `proof_obligation` fields. Remaining 33 TODO rows are
  intentional v0.4 placeholders (TensorOps GPU/CUDA/DLPack/
  KV-cache forward declarations + 3 ToolingMeta stubs).
  Generator carries 3-level resolution chain (`NAME_OVERRIDES`
  → `PATTERN_OVERRIDES` → `CLASS_DEFAULTS`). Schema vocabulary
  added `"sync"` effect tag for synchronization-only
  primitives.
- **CLI surface gate coverage (v0.2.64–86)** — 21+ unique
  user-facing CLI subcommands now under explicit smoke
  coverage in both `verify.sh` and `verify.ps1`. Step total
  grew 158 → 203. Includes the four meta-coverage steps:
  help-text-coverage gate (catches dispatched-but-unadvertised
  commands; v0.2.84 found `doc` and `fix`), JSON-flag smoke
  (11 commands; v0.2.86), version alias smoke
  (`--version`/`-v`/`-V`/`version`; v0.2.87), showcase build
  smoke (4 programs; v0.2.90), explain-full-spec-catalog
  (130 codes; v0.2.80), mojibake check (v0.2.91).
- **Drift gate hardening (v0.2.50–91)** — `tools/check_compiler_drift.sh`
  now enforces six things: s1↔tools-suite ABI parity,
  `helper_manifest.toml` freshness, `rod_manifest.toml`
  freshness, `RELEASES.md` freshness, CHANGELOG↔git tag parity
  (v0.2.83), and no UTF-8 mojibake in source/docs (v0.2.91).
  Single source of truth for the example list
  (`tools/examples.list`), rust_bridge artifact two-name
  detection (POSIX `libnucleor_rust_bridge.a` + Windows MSVC
  `nucleor_rust_bridge.lib`).
- **Compiler / tools-suite bug fixes (6 real bugs)** —
  v0.2.69 (`nuc test` target/ creation), v0.2.79 (4 explain
  registry codes missing) + v0.2.80 (44 more), v0.2.82
  (NUCLEOR_BOOTSTRAP_CONTRACT.md missing — referenced since
  v0.2.70), v0.2.83 (v0.1.67 git tag with no CHANGELOG entry),
  v0.2.85 (`nuc registry list` cmd.exe stderr leak), v0.2.91
  (CHANGELOG self-defeating mojibake). Each found via the
  audit pattern; each got a corresponding gate-step addition
  to lock down the drift class going forward.
- **Documentation staleness audit (v0.2.77–98)** — 19+ stale
  claims fixed across 12 doc surfaces (milestone tracker,
  helper-contract, schema docs, README, getting-started,
  language-tour, language-reference, migration guide,
  semver-and-release, contributing, rods-and-runtime,
  benchmarks, rfcs/README). Principal drift classes: POSIX
  target version (was v1.1, actually v0.3), rod count (was
  103, actually 121), `for`-loops "planned" (already work),
  hex/binary literals "not supported" (gate-tested daily),
  v0.1.x "out of scope" list (most items already shipped).
- **Bash gate clang fallback (v0.2.72 drive-by)** — added
  `C:\Program Files\LLVM\bin\clang.exe` as a Windows
  fallback for the bash `verify.sh` clang resolver, after a
  stale `LLVM_SYS_180_PREFIX` produced ~150 spurious link
  failures. Mirrors the PowerShell gate's behavior.
- **Orphan runtime C files — known v0.4 wrap targets (audit
  finding v0.2.123).** 11 files in `stdlib/runtime/*_rt.c`
  ship in the OSS distribution but have no `.nr` rod wrapper
  referencing them via `#cfile`, so users can't reach these
  features from Nucleor source today:
  - `activation2_rt.c` — SwiGLU, GELU, RMSNorm, RoPE, DyT,
    JumpReLU, QK-Norm, DeepNorm, SiLU
  - `attention2_rt.c` — FlashAttention-style tiled attention
    with online softmax, GQA, MLA, sliding window,
    differential attention
  - `transformer_rt.c` — scaled dot-product attention,
    multi-head attention, layer norm, feedforward,
    positional encoding, softmax, cross-entropy
  - `tokenizer_rt.c` — Byte-Pair Encoding (BPE) training +
    encode/decode, char-level fallback
  - `csv_rt.c` — CSV reading + writing, cell access
  - `queue_rt.c` — binary min-heap and max-heap with
    decrease-key (priority queue)
  - `thread_rt.c` — thread pool, futures, parallel map,
    barrier
  - `allocator_rt.c` — arena (bump) allocator, object pool,
    allocation stats
  - `diff_sim_rt.c` — differentiable quantum simulation
    (N cores, learnable noise logits, von Neumann entropy)
  - `rod_helpers_rt.c` — vec_push_s/get_s string-vec bridge,
    call_fn2/3 function-pointer callers
  - `mem_rt.c` — vec_free / vec_clear for long-running
    experiments
  Each compiles standalone (the file's leading `// Compile:`
  comment shows the manual command). Wrapping each in a
  `stdlib/rods/<name>.nr` is straightforward `extern fn`
  binding work. **No bug** — the implementations exist; only
  the user-facing surface is missing. Tracked as v0.4
  follow-up.
- **Orphan rod wrappers — known v0.4 example-coverage
  targets (audit finding v0.2.124).** 22 of the 121 rod
  files in `stdlib/rods/*.nr` ship with a `#cfile` to a
  runtime C file but are never `import`-ed by any example,
  test, or other rod, so the verify gate never compiles
  them through `nuc build`. The orphan set:
  - **ML / inference:** `conv` (CNN building blocks),
    `loss` (NN loss functions), `embedding`, `kv_cache`
    (paged LLM KV cache w/ eviction), `quantize`
    (Q4/int8/ternary/FP8), `speculative` (speculative
    decoding), `diffusion` (DDPM / rectified flow), `rl`
    (reinforcement learning), `checkpoint` (gradient-
    recompute checkpointing), `scan` (parallel-scan / SSM
    kernels)
  - **Quantum / numerics:** `mps` (Matrix Product States)
  - **Data / search:** `hnsw` (hierarchical navigable
    small-world index), `pq` (product quantization),
    `string_algo` (KMP, Levenshtein, Trie), `bioseq`
    (DNA/RNA/protein), `audio` (WAV/STFT/MFCC), `color`
    (color spaces / palettes), `mesh` (2D FE mesh +
    Laplacian)
  - **Systems / I-O:** `gpu` (GPU compute w/ guardrails),
    `comm` (distributed-training collectives), `serial`
    (serial port I/O), `stack` (LIFO over Vec)
  Each rod compiles via `nuc build` once an importer
  exists; the orphan status only means no example /test
  exercises the surface. Adding a one-import smoke for each
  in `examples/` (or a tests/rods/ corpus) will pull them
  under the gate without compiler changes. **No bug** —
  the rod sources are valid Nucleor; the user-facing
  example coverage is missing. Tracked as v0.4 follow-up
  alongside the v0.2.123 runtime orphan set.
- **Diagnostic-code coverage closure (v0.2.117–120)** —
  v0.2.117 brought EXPECT-headers to all 33 `tests/err/*.nr`
  files (bulk add of 28; 2 in v0.2.116; 3 already there).
  v0.2.118 added `err_tests_have_expect_smoke` to lock the
  property in via gate. The audit then exposed **23 codes**
  fired by the compiler but missing from spec doc + explain
  registry — 12 OWN-* (borrow checker), 10 TYP-* (type
  checker), 1 TNT-* (taint analysis). v0.2.119 wired 22
  (OWN+TYP); v0.2.120 wired the last (TNT). Spec catalog
  bumped 130 → 158 codes; **all 158 now wired and gated**.
  The "fired-vs-documented" drift class is closed.

## What's next

The v0.4 follow-on push picks up from
[`docs/milestones/v0.4.0.md`](../milestones/v0.4.0.md) — every
deferred row above is in there with the v0.2 release where the
foundation work landed, so v0.4 implementation picks up at "wire
it in" rather than "design it".

Highest-leverage v0.4 starting points (in order):

1. **Range patterns in match (RFC-0023 §3.1)** — `match x { 1..=5
   => ..., _ => ... }`. Drives MATCH-007 firing. Smallish parser
   change, large user-visible win.
2. **Generic enums (RFC-0024)** — unblocks compiler-integrated
   `Result<T,E>` / `Option<T>` (RFC-0016 phase 4) and the rest of
   the typecker chain.
3. **Iterator trait + adapter chain (RFC-0024)** — unlocks
   ergonomic stdlib idioms.
4. **Module resolver with `pub` enforcement (RFC-0018 phase 2)** —
   needs the symbol-table refactor; paired with generic enums.
5. **Stdlib audit + strict-mode flip (RFC-0015 phase 3+5+7)** —
   one coordinated push using `nuc fix --numeric` as the driver.
